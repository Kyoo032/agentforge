# Videos

Videos is a generate studio (prompt, aspect, duration, optional resolution, optional still, gallery). Without a gateway key the expected state is `videos-studio-needs-key` and a quiet Generate. Videos stays on the host route `ready` flag: a stub desk with `allowed: true` still quiets Generate. Chat, Documents and Images do not. Cloud must not paste a gateway key into the shared webdev Settings desk. Live Toko Token proof is the isolated matrix (gitignored `evidence/videos/live-matrix/`), not a generate from the stub studio.

## Sub-features

- `videos-rail` reaches `/videos` from `mode-videos` on Default.
- `videos-shell` shows `videos-studio`.
- `videos-needs-key` shows `videos-studio-needs-key` when no key is ready.
- `videos-empty` shows `videos-studio-empty` when the gallery has no clips.
- `videos-examples` shows the bundled example clips (`videos-example-card` × 6, each with a playing `videos-example-video` served from `resources/examples/videos/`); `videos-example-use-<templateId>` loads that template's prompt. Absent (not an error) on a checkout that has not run `pnpm videos:examples`.
- `videos-knobs` shows `videos-studio-aspect` and `videos-studio-seconds` in the open prompt bar; since 0.15.0 `videos-studio-resolution` (480p / 720p / 1080p) and — on image-to-video models only — `videos-studio-still` sit inside the closed `videos-studio-advanced` disclosure ("Advanced"), in the DOM but not visible until it is opened. A second disclosure, "Prompting rules", sits beside it. The header is the title plus `expected-inputs` = "You get: a generated clip, saved to the gallery below and downloadable." All three depend on the selected model ([`video-capabilities.ts`](../../../../packages/core/src/models/video-capabilities.ts)):
  - **Seconds** is `4 / 6 / 8` on any `veo_` id and `5 / 8 / 10` on everything else. `veo_3_1-fast` is the resolved default, so the page **opens on 4 / 6 / 8**. Switching model re-snaps the current value to the nearest allowed length (ties go shorter), so 10 s on a Seedance id becomes 8 s on Veo.
  - **Resolution** is enabled for the Seedance *wire* class, which the regex defines as `seedance | dreamina-seedance | doubao-seedance | veo_ | kling | sora` — wider than the name suggests. It is disabled on `grok-imagine-video`, `mj_video` and `omni-fast-v2v`, and the field is dropped from the POST body entirely in that case.
  - **Still** is not rendered at all when the model is not image-to-video: count 0 on `mj_video` and `omni-fast-v2v`, count 1 on `grok-imagine-video` and the Seedance / Veo ids. A muted "text to video only" line takes its place. Do not assert the field unconditionally.
- `videos-estimate` shows the pre-generate cost line `videos-studio-estimate` under the knobs row ("≈ $0.60 for 5 s at 720p · $0.12/s · <vendor> list price, checked <date> · <tier>") plus `videos-studio-estimate-compare`; an id with no transcribed per-second price shows `videos-studio-estimate-unknown`. Each `videos-studio-model` option ends with its own `$x.xx/s` tag. Table: [`docs/internal/research/media-pricing.md`](../../../../docs/internal/research/media-pricing.md). Maps: [`generate-studios.md`](../../../../docs/internal/maps/generate-studios.md) (prompt bar → picker → generate helper → gallery), [`media-cost-estimate.md`](../../../../docs/internal/maps/media-cost-estimate.md) (the price line), [`renderer-media.md`](../../../../docs/internal/maps/renderer-media.md) (why the gallery `src` is always host-served).
- `videos-ingest` — a successful generate also writes a `Videos` work card to the Knowledge Base (prompt, model, aspect, duration, `media:<id>` pointer; no bytes). `videos-example-use-*` only loads a prompt and never adds a source. See [knowledge-ingest.md](./knowledge-ingest.md).

## How to get to it (user POV)

- Choose Videos on the left rail (`mode-videos`). Default already has the tab.
- Open `http://127.0.0.1:3000/videos` when the tab is unlocked.

## Driving it with the DPSBuddy harness

Preconditions:

- Doctor exits 0.
- `mode-videos` is visible. If not, skip with that precondition — same rule as Images.
- Do not submit `videos-studio-submit` on the shared Cloud `:3000` desk. Isolated live matrix (in-process key, never Settings) is the Cloud live proof. On Windows, only generate from the product UI if the operator asked.

- **Open Videos.** Click `mode-videos`. URL matches `/videos` (15s). `videos-studio` is visible (15s).
- **No-key state.** `videos-studio-needs-key` is visible when the studio is not ready (no key). Copy points at Settings. The copy is rendered by `SettingsLinkHint`, so the banner always contains exactly one `<a href="/settings">` — assert the anchor, not the word "Settings", which is locale-dependent. Driven 2026-09-17 on the `id` desk: `Tambahkan kunci gateway Toko Token di Pengaturan untuk membuat video.`
- **Empty gallery.** `videos-studio-empty` reads that nothing is here yet when there are no clips. On the owner's `:3000` desk this sub-feature is **unreachable**: the gallery carries 37 stub video rows left on that desk (`docs/internal/unreleased.md:37`). Record `verified-unreachable (empty gallery)` rather than failing it, and never delete rows to reach the state.
- **Knobs.** `videos-studio-aspect` and `videos-studio-seconds` are visible on load; `videos-studio-resolution` and `videos-studio-still` are not. Click the `videos-studio-advanced` summary and both become visible (driven 2026-09-23; estimate then read `≈ $0.75 for 5 s at 720p …`). Example gallery stays. Do not generate.
- **Example use does not ingest.** Click a `videos-example-use-*`, then open `/knowledge`: no new `Videos` row and `knowledge-loop-work` unchanged. Only a real `POST /api/v1/videos` (live generate, operator asked) adds a `Videos` source; the gallery leaves `videos-studio-empty` at the same time.
- **Cost estimate.** With a model selected, `videos-studio-estimate` is visible and starts with `≈ $`. Double the clip and the total doubles — on the default `veo_3_1-fast` that is 4 → 8 s, on a Seedance id it is 5 → 10 s. **Read the options out of `videos-studio-seconds` before picking one**; the set is model-dependent (see `videos-knobs`). Change `videos-studio-resolution` 720p → 480p on a Seedance id and both the total and the `$/s` drop. Select `mj_video` and the price line is omitted. No POST, no key, no network: `GET /api/v1/videos` prices the list from the curated table plus an already-cached gateway catalog, and only the POST handler calls `requireGatewayAllowed`. A selected model is the only requirement. Driven 2026-09-15 at 1440x900: `videos-studio-estimate` read `≈ $0.40 for 4 s at 720p · $0.10/s · Google list price, checked Sep 15, 2026 · cheap` and `videos-studio-estimate-compare` read `About 4× cheaper than veo_3_1`. Driven 2026-09-17 at 1280x800 on the keyless `:3000` desk, locale `id`: `veo_3_1-fast` 4 s / 720p read `≈ $0.40 untuk 4 dtk pada 720p · $0.10/dtk · Harga resmi Google, dicek 15 Sep 2026 · murah` with `videos-studio-estimate-compare` `Sekitar 4× lebih murah dari veo_3_1`; at 8 s it read `≈ $0.80`. `seedance-2.0-fast` walked 5 s/720p `≈ $0.60 · $0.12/dtk` → 10 s/720p `≈ $1.20` → 10 s/480p `≈ $0.60 · $0.06/dtk` → 10 s/1080p `≈ $3.00 · $0.30/dtk`. `mj_video` fell to `videos-studio-estimate-unknown`. `omni-fast-v2v` read `~… · Perkiraan belum terverifikasi, tanpa halaman resmi vendor · murah · (belum terverifikasi)` and named no vendor, as required.
- **Locale (id).** With the desk on `id` (see [locale.md](./locale.md)), this view reads `Video`, `Belum ada apa pun`, `Buat video untuk mengisi galeri ini.` and `Contoh klip`. Testids are locale-invariant.
- **Other handles on this page.** `videos-studio-prompt-bar` (the `<form>`), `videos-studio-prompt` (the text input), `videos-studio-gallery` (the grid section), `videos-studio-download` (one per gallery clip), `videos-studio-error` (the red box, `role="alert"`), `videos-enhance` (the Enhance button), `videos-examples` (the bundled-clips section) and `videos-examples-error` (shown when `GET /api/v1/videos/examples` fails). - **IDE proof.** Screenshot of the shell and needs-key banner under `evidence/videos/<run-id>/`.
- **Cloud stub.** `foundation.spec.ts` asserts `videos-studio` and `videos-studio-needs-key`. That is the stub contract. Do not generate from the shared desk.

## Gotchas

- `videos-studio-needs-key` is the stub pass. A missing banner on a keyless Cloud run is a product fail.
- The studio posts to `/api/v1/videos` (gateway `POST /v1/video/generations` plus poll), not `/runs/video`. A keyless submit is a 400.
- Live Seedance-class jobs on this prepaid test key are **403** (`prepaid_async_requires_fixed_price`). That is a billing/proxy class, not a knob or key-format fail. Grok Imagine video is the live generate proof on this key.
- Do not save the test key to shared `:3000` Settings. That flips the whole local webdev to live.
- Optional still uses `videos-studio-still`. Leave it empty for the shell proof.
- A `Videos` source on `/knowledge` is a text card pointing at `media:<id>`. Do not look for an mp4 under `data/media/knowledge/`.
- The estimate is the **provider list price per second**, not the Toko Token rate (which is lower). The line leads with `≈` when exact and `~` when softened, never both: `seedance-2.5` has no published 1080p tier so it falls back to 720p, and `omni-fast` is low confidence, prints "Unverified estimate, no vendor page" and "(unverified)", and names **no vendor** — if you ever see it attributed to Google, that is a bug.
- `videos-studio-estimate-compare` is prefixed `~` when the model it names was itself estimated from a fallback tier. At 1080p most Seedance peers are fallbacks, so the whole comparison is softened there.
- The gateway price catalog is never used for video: a flat per-call catalog rate is not a per-second rate, so an unpriced video id stays on `videos-studio-estimate-unknown`.
- `videos-studio-resolution` is a Seedance-class field. grok-imagine / default OpenAI-like models keep seconds + still and must not send `ratio` / `resolution` on the wire. The live matrix confirmed grok rejects `ratio`.
- **On a fallback tier, changing `videos-studio-resolution` can move only the tier word.** `veo_3_1-fast` has a 720p tier and nothing else, so 480p and 1080p both fall back to 720p: the number and the `$/s` are byte-identical across all three, and only the cheap/mid/premium word changes (driven: 480p read `menengah`, 1080p read `murah`), because the tier word ranks the model against its peers *at the resolution that was asked for*. A test that asserts "the number moves when resolution moves" fails on the default model and is asserting the wrong thing.
- **`videos-studio-submit` is disabled while the studio is not ready**, so a keyless desk cannot generate from the UI at all (`apps/web/components/videos-studio.tsx:323`). `images-studio-submit` is **not** gated the same way (`apps/web/components/images-studio.tsx:204`) — it stays clickable with no key and returns a 400. Do not carry an assumption from one studio to the other.
- **`videos-studio-model` and `videos-enhance` have no literal `data-testid=` in the source.** They are passed as `testId` props (`apps/web/components/videos-studio.tsx:248`, `:307`) and applied inside `ModelSelect` / `EnhancePromptButton`. Grepping `apps/web` for `data-testid="videos-studio-model"` returns nothing; the handle is real and `getByTestId` finds it. Same for `images-studio-model` / `images-enhance`.
- A visited studio stays mounted — SKILL.md harness-wide gotcha **G3**. Here that means `example-gallery` / `example-card` / `example-result` resolve to two elements after `/images` → `/videos`, so scope those queries to `videos-studio` or use `.first()`.
- **Do not snapshot the page the moment `videos-studio` becomes visible.** `loading` starts true and suppresses both `videos-studio-needs-key` and `videos-studio-empty`; a snapshot taken then reads neither. Wait for `videos-studio-model` to gain options (that is `GET /api/v1/videos` landing) before asserting either one — the general settle rule is SKILL.md harness-wide gotcha **G1**.
