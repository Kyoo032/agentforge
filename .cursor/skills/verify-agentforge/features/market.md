# Market

Market is a job: a named desk picked in the left rail, that desk's own watchlist of up to 15 tickers from any market, and a briefing instruction → the host fetches quotes, bars at that desk's depth, TradingView ratings, headlines, and macro levels on the user's machine, computes the rest (signals, rotation, sessions, swings, metals) in code, builds a chart per ticker, and the model writes a briefing (Bahasa Indonesia by default) over that data packet → guarded briefing → DOCX. It is analysis, not investment advice, and it never tells the reader to buy or sell now. Runs inside the host like Research, Data, and Finance: no server, no sidecar, no port, no Settings fields. Landed on `feat/market-mode` (2026-09-09, v2); see `docs/internal/0.14.25-changelog.md` and `docs/internal/market-mode-plan.md`.

## Sub-features

- `market-header` (0.15.0) — title plus one outcome line in `expected-inputs`: "You get live prices and a chart per ticker, plus a written briefing — type up to 15 tickers, no file upload. Analysis, not investment advice." The rail's `rail-market-specialists-toggle` is arrow-only (`Show specialists` in `aria-label` / `title`). Driven 2026-09-23: `rail-market-specialist-crypto` → `/market?specialist=crypto`, `market-specialist-current` `Crypto`; watchlist not edited, briefing not generated.
- `market-rail` (a recipe name, not a testid) is the rail entry: `mode-market` on Home, between Data and Images, reaching `/market`. On an expanded rail the Market row also carries the specialist block — `rail-market-mode` wraps the row, `rail-market-specialists-toggle` is the chevron on it, `rail-market-specialists-branch` is the indented wrapper with the hairline guide, and `rail-market-specialists` is the scroll container of rows inside it. That block is where the agent is chosen (see the named-agent bullet below); its chrome half — the block exists, it disappears when the rail collapses — belongs to [rail.md](./rail.md).
- `market-board` renders as soon as a chip exists, with no gateway key: one `market-board-card` per ticker carrying `market-board-price`, `market-board-close`, `market-board-facts`, `market-board-card-note`, and `market-board-chart`; `market-board-loading` is the skeleton grid while the fetch is in flight. `market-board-status` names the session, `market-board-refresh` refetches, `market-board-error` / `market-board-failures` explain a source that is down. Served by `POST /api/v1/market/board`, which fetches quotes, bars, and technicals only (no headlines, no macro, no model) and names no desk.
- Every price chart carries range buttons (1M / 3M / 6M / 1Y / 2Y, default 6M) and plots close + SMA50 + SMA200 on an axis that follows the data rather than anchoring at zero. The buttons live in `<chart testid>-ranges` (`market-board-chart-ranges` on the board, `market-chart-ranges` in the preview) and have **no testid of their own** — select them by `data-range`, whose values are lowercase (`1m`, `3m`, `6m`, `1y`, `2y`) even though the labels read `1M`…`2Y`. The plotted point count per range is 22 / 66 / 126 / 252 / 504. The **board** fetches 36 months, so even the 2Y window has the 199 bars of lead-in SMA200 needs; a shorter fetch silently drops both averages at 2Y. A **briefing** fetches its desk's own depth instead (6, 12 or 24 months), so a preview chart can legitimately be shorter than the board's for the same ticker.
- `market-studio` is the page. Inside it `market-inputs` is the form, and `market-watchlist-input` is the chip box holding the text field `market-tickers`, the chips `market-ticker-chip`, the suggestion list `market-ticker-suggest` with `market-ticker-option` rows, and the refusal `market-ticker-notice`. While the watchlist is empty the form shows `market-starters` (one `market-specialist-starter` plus three `market-starter` buttons) and `market-studio-empty` ("Add a ticker above to see its price and chart.") — a state you now have to reach by removing every chip, because a desk opens seeded from its own starter list. The technical settings are behind `market-options-toggle`: the panel `market-options` holds `market-prompt` (with `market-prompt-reset`), `market-position`, `market-maxchars`, `market-studio-model`, `market-enhance`. `market-language`, `market-generate` and, while a run is live, `market-cancel` stay in the open. There is no `market-shell`.
- Market ships one pipeline and eleven named agents, and the agent is chosen in the **rail**, not in the studio. `rail-market-specialists` (a `role="group"` container inside `rail-market-mode`) holds one `rail-market-specialist-<id>` row per agent in core order: `saham`, `forex`, `gold`, `crypto`, `commodities`, `indices`, `sector-rotation`, `scanner`, `summary`, `elliott-wave`, `news`. Each row links `/market?specialist=<id>` and the open one carries `aria-current="true"`; `rail-market-specialists-toggle` is the chevron (`aria-expanded`). The block is open exactly while the user is on `/market` — selecting any other rail item minimises it, coming back opens it again, and nothing is stored. The rows are a height-adaptive scroll container carrying `data-overflowing="true|false"` (four rows at 720 and 768, about seven at 900, all eleven from 1008 up), with a fade mask only while rows are cut off. **`market-specialist` — the old `<select>` — no longer exists; its count is 0.** The studio only reports the desk: `market-specialist-current` is the label, `market-specialist-hint` the one-line description, `market-specialist-sources` the provenance badge, and `market-specialist-starter` fills the watchlist with that agent's own starter tickers alongside the three `market-starter` presets. That header block is mounted above the starters while the watchlist is empty and beside `market-language` once a chip exists — never both at once. Choosing an agent (or a language) rewrites `market-prompt` to that agent's default instruction **only** while the box still holds one of ours; a prompt the user typed is left alone, and `market-prompt-reset` goes back to the current agent + language default. The chosen agent rides in the request body as `specialist`, comes back on the briefing, and is named in `market-briefing-specialist` above the artifact actions. The rewrite route needs no field of its own: it reads the agent off the briefing.
- Each agent keeps **its own watchlist**, per desk. The chips live in `localStorage` under `agentforge-market-watchlist:<workspaceId>:<specialist>` (a null workspace is the literal `home`), seeded from that agent's starter list the first time it is opened, deduped and capped at 15 on every write. Switching agents in the rail swaps the chips and the board with them: the crypto desk's coins never appear on the gold desk, and a chip added to one desk is still there when you come back to it. Clearing the key is what makes a desk open from its starters again.
- `market-specialist-sources` sits under `market-specialist-hint` inside the same header block, so it rides along to whichever of the two placements is mounted. It is one muted line naming the providers behind that agent's harness, deduped and in source order: `Sumber: Yahoo Finance · TradingView · CoinGecko · Dihitung di perangkat` on an `id` desk, `Sources: …` with `Computed on device` on `en`. Quotes, history, headlines, macro, fundamentals, insiders and global news are Yahoo Finance; technicals are TradingView; the crypto section is CoinGecko; the sentiment section is the **two** venues `StockTwits · Reddit`; swings, metals, signals, rotation and sessions never leave the machine. So `crypto` reads `Yahoo Finance · TradingView · CoinGecko · StockTwits · Reddit` and `saham` ends `· StockTwits · Reddit` too, `elliott-wave` reads `Yahoo Finance · Dihitung di perangkat` (`Yahoo Finance · Computed on device` on `en`), and `scanner` reads all three of Yahoo, TradingView and the on-device label. The vendor names stay in English in both locales. A web-research desk earns no `· Web` item today: nothing the studio already loads says whether a web key is configured, and the badge does not promise a source it cannot see.
- **Depth.** `market-depth` is a `role="group"` segmented control mounted beside `market-language` once a chip exists, and beside the header block above the starters while the watchlist is empty — the same two placements as `market-specialist-current`, never both at once. It is headed `Analysis` / `Analisis` and holds `market-depth-quick` (labelled `Single analyst` / `Analis tunggal`, default, `aria-pressed="true"`) and `market-depth-team` (`Analyst team` / `Tim analis`); the **wire values stay `quick` and `team`** whatever the labels read, and the chosen one rides in the request body as `depth`. The track hugs its two buttons — it is `w-fit`, not stretched to the flex row. A desk whose harness names no analysts (`scanner`, `sector-rotation`, `elliott-wave`) keeps the control visible but `market-depth-team` `disabled`, with the muted line `market-depth-unavailable` saying why ("This desk has no analyst team, so a single analyst writes its briefing.") — on every other desk that line is `market-depth-hint` instead. Choosing `Analyst team` and then clicking one of those three rail rows resets the state to quick, and coming back does **not** re-arm it.
- `market-team` is the analyst-team panel under the briefing sections and above `market-watchlist`, rendered **only** when the run carried a team (a quick briefing has none, so its count is 0). It starts collapsed: `market-team-toggle` (`aria-expanded`) opens four analyst cards `market-team-analyst-technical` / `-fundamentals` / `-sentiment` / `-news` (each with a confidence chip and `data-confidence` low / medium / high), the two debate columns `market-team-bull` and `market-team-bear`, and the three lenses `market-team-risk-aggressive` / `-neutral` / `-conservative`. Every string in it is model output rendered as plain text — no markdown, no HTML — so a note containing markup shows as characters.
- "Write a briefing" without a gateway key shows `market-error` "Quotes and charts work without a key. To write the briefing, add your API key in Settings." plus the `market-error-settings` link. The studio posts `/api/v1/market/stream`, so that refusal arrives as **HTTP 200 carrying an `event: job.error` frame** with `code: "runtime_stub"` and `status: 503` inside it — assert the `market-error` testid, never the HTTP status (SKILL.md **Harness-wide gotchas** G2). Only the non-stream `POST /api/v1/market` answers a real 503. Prices and charts keep working. A malformed body is 400 `invalid_request` whatever the runtime. An unresolvable symbol is listed in `market-failures`, never a crash.
- Live generate runs `market-progress` phases resolving → quotes → technicals → charts → news → macro → drafting (with "Still drafting… Ns" heartbeats) → verifying → saving. A desk that does not list headlines or macro simply skips those phases. A **team** run inserts analysts → debate → risk → synthesis in place of drafting; those four labels come from the web catalog (`market.progress.*`, so they read `Catatan analis`, `Ronde bullish dan bearish`, `Pembacaan risiko`, `Menulis briefing` on `id`) while every packet phase above still shows the host's English label.
- `market-preview` renders `market-clock` (session badge `data-session` pre / regular / post / closed + note), the model sections `market-section` with `market-section-regen`, `market-guard` (`data-clean`), `market-watchlist` rows, a `market-ticker-card` per ticker with `market-chart` (SVG line: close, SMA50, SMA200), `market-ticker-facts`, `market-headline` links, `market-macro` rows, `market-sources`, `market-disclaimer` (stamped by code, never editable), `market-failures` (sources that were down; a note, not a fail). Also in this view and not named above: `market-section-guarded` (the advice guard replaced part of that section), `market-headlines` and `market-ticker-failures` on each `market-ticker-card`, the `market-watchlist-row` / `market-macro-row` rows inside `market-watchlist` / `market-macro`, the shared artifact set `market-actions` with `market-actions-note`, and the rewrite panel `market-regen-panel` with `market-regen-prompt`, `market-regen-model`, `market-regen-file`, `market-regen-attach`, `market-regen-submit` — the regen ids come from `JobRegenPanel` mounted with `testIdPrefix="market"`, not from `market-briefing-view.tsx` itself, so a literal grep of that file misses them.
- `market-download` builds a DOCX with the disclaimer under the title and as the last paragraph; charts export as tables. `market-send-kb` (type Brief), `market-make-document`, `market-make-presentation` via the shared artifact actions.

## How to get to it (user POV)

- Choose Market on the left rail (`mode-market`). Home has the tab. The desk list opens under it; pick the agent you want before typing tickers.
- Open `http://127.0.0.1:3000/market` when the tab is unlocked. `?specialist=<id>` opens straight onto one desk.
- Legal / Marketing / Students presets do not add this tab unless the owner checks it.
- Nothing to install and nothing to configure beyond the gateway key. Web search is used when a Tavily/Brave key exists and the chosen desk asks for it; otherwise headlines come from Yahoo.

## Driving it with the DPSBuddy harness

Preconditions:

- Doctor exits 0 and `modeKeys` includes `market`.
- `mode-market` is visible on Home. If count is 0, you are on a desk that hid it.
- Stub proof stops at the rail desks, chips, starters, and the generate refusal. Live generate only if the operator asked and doctor reports `runtime: "ai"` and `hasOpenai: true`. Live needs the internet for Yahoo Finance, the TradingView scanner and (crypto desk only) CoinGecko / Binance; a source that is down shows in `market-failures` and the briefing still builds.
- The watchlist keys are the operator's state. Read `localStorage` for `agentforge-market-watchlist:*` before touching any chip and restore them at the end, or drive on a throwaway profile.
- Unit proof is Vitest in `packages/core` (`src/market`, including `harness`, `specialists`, `signals`, `rotation`, `sessions`, `packet-sections` and `swings`), `packages/host` (`src/market` including `packet-harness`, `coingecko` and `metals`, plus `market-generate`, `market-board`, `market-briefing-build`, `market-docx`, `handlers/market`) and `apps/web` (`market-client`, `use-market-board`, `chart-scale`, `market-specialist`, `market-specialist-wiring`, `market-depth`, `market-team-wiring`, `market-watchlists`, `rail-market-specialists-wiring`, `market-headline`, `market-locale`, `market-locale-catalog`). No sockets in tests.

- **Collapsed rail.** Click `rail-collapse`. `rail-market-mode`, `rail-market-specialists-branch`, `rail-market-specialists`, `rail-market-specialists-toggle` and every `rail-market-specialist-*` are count 0. Click `rail-expand` before carrying on.

- **Live.** Only after doctor `ai`: click `market-options-toggle`, paste `MU: $100 @ $860, $200 @ $900, target $1,000` in `market-position`, generate. ## Gotchas

- A briefing that reads "beli sekarang", "jual sekarang", "buy now", "sell now", "you should buy" is a C1 leak: the sentence is replaced with `[removed: directive language]` and counted in `market-guard`; the API rejects such a briefing on `/market/docx` and `/market/regenerate` with 502 `advice_leak`. Ranking, sentiment, targets, and levels are allowed.
- `[unverified figure]` in a section means the model wrote a number that is not in the packet, the headlines, or the position context. Index names (`S&P 500`, `Nasdaq 100`), `50-day` / `200-hari` labels, and `24/7` publisher clocks are not figures. One or two real flags on a long briefing is a note; many is a fail (check the packet block rounding).
- **A fresh desk is not empty.** Every agent opens seeded from its own starter list, so `market-studio-empty` and `market-starters` are count 0 on first load. Remove every chip to reach that state deliberately.
- **The rail block lives on `/market` only, and nothing about it is stored.** Off `/market` `rail-market-specialists-branch` and `rail-market-specialists` are both count 0 and `rail-market-specialists-toggle` is `disabled` with `aria-expanded="false"`; the chevron's close is forgotten the moment you leave. There is no `agentforge-rail-market-specialists` key and no rail-prefs entry — do not assert one.
- **The rows scroll.** Four rows are in view at 720 and 768, about seven at 900, all eleven from 1008 up; while rows are cut off the container carries `data-overflowing="true"` and a fade mask. Scroll the row into view (or use its element handle) instead of assuming it is clickable, and do not read the fade as a rendering bug.
- A run outside 04:00–09:30 ET is labelled by `market-clock`; the default prompt tells the model to say so. That is correct behaviour, not a bug.
- Yahoo, TradingView or CoinGecko being down is a note when the briefing still builds from the rest; a fail only when the studio hangs or invents figures.
- The 15-ticker cap is silent. At `WATCHLIST_MAX = 15` (`packages/core/src/market/watch-schemas.ts:30`) the `market-tickers` input goes `disabled` with the placeholder "That is the maximum" / "Itu sudah batasnya"; `market-ticker-notice` is not shown, even though `watchlist.overflow` copy exists in both catalogs. Assert the `disabled` attribute, not a notice. Pasting past the cap adds chips up to 15 and stops, also silently.
- `market-download` and `market-position` are each on two elements once a result exists (the studio button and the shared artifact bar; the options input and the preview's position section). Use `.first()` or scope the query.
- Do not POST `/api/v1/market` as a substitute for the studio on a live proof — it is the only Market route that answers a real 503, so it proves the wrong thing about the studio.
- The operator's `:3000` desk does not restart on host changes; drive new host code on an isolated instance (`PORT=3177`, own `AGENTFORGE_DATA_DIR` + `AGENTFORGE_SETTINGS_PATH`), and delete that data dir afterwards if a key was saved there.
