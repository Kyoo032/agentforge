# Finance

Finance is a task mode: the rail picks one of five tasks, the URL carries it (`/finance?task=<id>`), and each task has its own inputs, its own phase strip and its own result — then one export in Excel, PowerPoint or Word. It is not a spreadsheet. There are no starter cards and no canned preview: every result comes from a live generate, so the whole result-and-download surface needs a working gateway key. The host never invents figures. How it works underneath: [`docs/internal/maps/finance-parse-and-generate.md`](../../../../docs/internal/maps/finance-parse-and-generate.md), and the task catalog in [`docs/internal/maps/finance-tasks.md`](../../../../docs/internal/maps/finance-tasks.md).

## Sub-features

- `finance-rail` reaches `/finance` from `mode-finance` on Default (and any workspace that includes Finance).
- The Finance rail row carries a chevron, `finance-tasks-toggle`, which opens `rail-finance-tasks` (with `rail-finance-tasks-branch`) holding one `finance-task-<id>` row per task: `finance-task-brief`, `finance-task-cashflow`, `finance-task-budget`, `finance-task-appraisal`, `finance-task-ratios`. Each row is `/finance?task=<id>`. **All five run today** — none shows an unavailable panel.
- `finance-shell` shows `finance-studio` with `finance-task-current`, `finance-task-hint`, `finance-phase-strip`, the empty copy `finance-studio-empty` and the prompt bar `finance-studio-prompt-bar`. All of them are on the page from load, on every task.
- `finance-phase-strip` holds one `finance-phase-<id>` per phase of the open task: 6 for `brief`, 6 for `cashflow`, 7 for `budget`, 6 for `appraisal`, 6 for `ratios`. The ids differ per task — `finance-phase-paste-figures` on the brief, `finance-phase-monthly-flows` on cash flow, and so on.
- The prompt bar is shared by every task: `finance-enhance`, `finance-studio-model`, `finance-prompt`, `finance-generate`, plus `finance-cancel` only while a generate is running.
- Four tasks mount the shared inputs ids `finance-inputs`, `finance-figures-input`, `finance-parse`. **Ratios does not**: it mounts `finance-ratios-inputs`, `finance-ratios-figures` and `finance-ratios-parse` instead, with `finance-ratios-bands` / `finance-ratios-bands-reset` and `finance-ratios-buckets` beside them.
- Brief-only inputs: `finance-items` / `-row` / `-label` / `-amount` / `-add`, `finance-param-discountRatePercent`, `finance-param-fixedCosts`, `finance-param-pricePerUnit`, `finance-param-variableCostPerUnit`, and `finance-dataset` when the desk has a saved dataset. `finance-stated-facts` (with `finance-stated-fact`, `-label`, `-value`, `-sentence`, `-remove`) appears only after a parse of a document that stated figures in sentences.
- Task-specific inputs: `cashflow-opening-cash`, `cashflow-periods` (or `cashflow-no-periods`), `cashflow-what-if` with `cashflow-lever-<key>`; `budget-flag-mode`, `budget-pairing`, `budget-error`; `appraisal-flows`, `appraisal-add-year`, `appraisal-preview`.
- `finance-upload` is the file upload inside the inputs panel on every task, between the parse button and the dataset picker: `finance-upload-input`, `finance-upload-drop`, `finance-upload-preview`, `finance-upload-sheet` (only for a file with more than one sheet), `finance-upload-warnings`, `finance-upload-pii`, `finance-upload-use`, `finance-upload-remove`, `finance-upload-error`. It reads the file on the host (`POST /api/v1/finance/import`) and needs no model.
- A successful generate adds `finance-export` and `finance-export-toggle` (with `finance-export-menu` holding `finance-export-xlsx`, `finance-export-pptx`, `finance-export-docx`, and `finance-export-error`), `finance-result-pii` and `finance-result-model-fallback` when there is something to say, and the shared artifact bar `finance-actions`, `finance-download`, `finance-send-kb`, `finance-make-document`, `finance-make-presentation`, `finance-actions-note`. None of them are in the DOM on load.
- The brief's result adds `finance-charts` (or `finance-charts-empty`) with one `finance-chart-<id>`, then `finance-preview`, `finance-guard`, `finance-section`, `finance-section-regen`, `finance-metrics`, `finance-table`, `finance-assumptions`. The other four tasks have their own result roots: `cashflow-result`, `budget-result`, `appraisal-result`, `finance-ratios-result` (each with a `*-no-report` sibling when the run came back without one).
- `finance-progress` (with `finance-progress-round`, `finance-progress-phase`, `finance-progress-sources`) exists only while a generate is in flight. It never appears on a keyless desk: `requireLive` throws before the first `job.phase` is emitted.
- `finance-auto-parsed` covers Generate pressed with figures in the brief but no confirmed rows and no dataset: the brief itself goes to `/api/v1/finance/parse`, the rows land in the editor, and the click stops there.
- Generate POSTs `/api/v1/finance/stream` on every task. Parse POSTs `/api/v1/finance/parse` with the task on the body; export POSTs `/api/v1/finance/export`.
- Stub/no-key generate shows `finance-error` with the gateway refusal. The status is asymmetric per route: `/api/v1/finance/parse` is a real HTTP **503**, while `finance-generate` → `/api/v1/finance/stream` is HTTP **200** with the 503 inside a single `job.error` frame. Assert `finance-error`, never the generate route's status; see SKILL.md “Harness-wide gotchas” G2.

## How to get to it (user POV)

- Choose Finance on the left rail (`mode-finance`). Default already has the tab.
- Open `http://127.0.0.1:3000/finance` when the tab is unlocked. That is the brief; the chevron on the Finance row opens the other four tasks.
- Legal / Marketing / Students presets do not add this tab unless the owner checks it.

## Driving it with the DPSBuddy harness

Preconditions:

- Doctor exits 0.
- `mode-finance` is visible on Default. If count is 0, you are on a desk that hid Finance — switch to Default or add the tab in Workspaces.
- Keyless proof stops at the shell, the task walk, the upload and the generate refusal. There is no keyless route to a result or a download. Live generate only if the operator asked and doctor reports `runtime: "ai"` and `hasOpenai: true`.

- **Open Finance.** Click `mode-finance`. URL matches `/finance`. `finance-studio`, `finance-task-current`, `finance-task-hint`, `finance-phase-strip`, `finance-studio-empty`, `finance-studio-prompt-bar` and `finance-inputs` are visible. `finance-export` and `finance-download` have count 0.
- **Walk the five tasks.** Click `finance-tasks-toggle`; `rail-finance-tasks` opens with five `finance-task-<id>` rows. Click each in turn. The URL becomes `/finance?task=<id>`, `finance-task-current` reads that task's name, and `finance-phase-strip` shows **its** phases — count 6, 6, 7, 6, 6 for brief, cashflow, budget, appraisal, ratios. On `cashflow`, `budget` and `appraisal`, `finance-inputs` has count 1. On `ratios` it has count **0** and `finance-ratios-inputs` has count 1 — that is the design, not a missing panel. An unknown `?task=nope` falls back to the brief with no error.
- **Generate needs the brief.** `finance-generate` is disabled until `finance-prompt` is non-empty (`disabled={locked || !prompt.trim()}`). Fill `finance-figures-input` alone and it stays disabled — pasted figures never enable it. Type the brief first on every step below.
- **Generate without a key.** Fill `finance-prompt` and click `finance-generate`. `finance-error` mentions gateway / Settings / API key. On an `id` desk the text is exactly `Finance memerlukan gerbang yang aktif. Tempel kunci API Toko Token di Settings, lalu coba lagi.` (`gatewayRequiredMessage("finance", …)`, `packages/core/src/output-language.ts`); in `en` it is `Finance needs a live gateway. Paste a Toko Token API key in Settings, then try again.` The studio appends no extra Settings link because the message already contains "Settings" (`needsSettingsHint`, `finance-studio.tsx:48-50`, `:309`).
- **Generate with figures only in the brief.** On `/finance?task=brief`, with no confirmed rows and no dataset, put the numbers in `finance-prompt` ("Q3 2026 review: revenue IDR 18.4B, COGS IDR 7.9B, opex IDR 6.1B") and click `finance-generate`. `briefLooksLikeFigures(prompt)` is true (any digit, or a currency token IDR/Rp/USD/EUR/$/€/£/¥/%), so the brief POSTs to `/api/v1/finance/parse`, the rows fill `finance-items`, `finance-auto-parsed` shows the row count, and the click **stops** — it never chains into a generate. Click `finance-generate` a **second** time to draft. Without a key the same click shows the parse failure in `finance-error`, not the add-items message.
- **Parse is not uniformly keyless-refusing.** On `brief`, `finance-parse` without a key answers 503. On `cashflow`, `budget` and the grid path of `appraisal` the host reads the figures in code and never calls the gateway, so the same button can succeed on a keyless desk; `ratios` only reaches the gateway when a label needs placing. Record what each task's parse actually answered rather than assuming a 503.
- **No result without a model.** `result` is set only by a successful generate or a section regen, so neither `finance-export` nor `finance-download` is reachable without a working gateway key. On a keyless proof record count 0 for both and stop there. `finance-upload` is the exception: it is in the DOM on a keyless desk and its `/api/v1/finance/import` call answers 200.
- **Upload a spreadsheet.** On `/finance?task=brief`, set `finance-upload-input` to a small `.csv` (two columns, label and amount). `finance-upload-preview` appears with the first rows, then `finance-upload-use` fills `finance-figures-input` with the same figures as plain text — **read the textarea value**, that is the proof. Type a line into `finance-figures-input` first and upload again: the new text is appended on its own line, nothing typed is lost. `finance-parse` then runs the normal parse; no row reaches `finance-items` without it. `.pdf`, `.docx` and `.pptx` are accepted too (their tables become sheets); anything else is refused in `finance-upload-error` and nothing changes in the box. A file over 25 MB is refused with HTTP 413.
- **Charts above the prose.** After a successful brief generate, `finance-charts` sits between `finance-actions` and `finance-preview`, with one `finance-chart-<id>` per series the report carries (`finance-chart-margin-growth` on the brief). A brief whose figures have no periods to plot renders `finance-charts-empty` instead — that is the report having no chart, not a broken chart. Cash flow draws `finance-chart-cash-balance` / `-net-cash`, appraisal `finance-chart-cumulative-cash-flow` / `-sensitivity`, ratios `finance-chart-gauge-<key>`; budget draws `budget-variance-bars` instead of `finance-charts`.
- **Export in three formats (live only).** After a successful generate, click `finance-export`: `POST /api/v1/finance/export` **200** with `content-type` `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` and a `.xlsx` filename in `Content-Disposition`. Then `finance-export-toggle` → `finance-export-pptx`: the same route answers the `presentationml.presentation` type and a `.pptx` name; `finance-export-docx` answers the `wordprocessingml.document` type. The button label then reads the format you last picked, and it still reads it after a reload — the choice is stored per desk. Record status, content type and byte length for each; the first four bytes of the xlsx and the pptx are `504b0304`.
- **Locale (id).** With the desk on `id` (see [locale.md](./locale.md)), this view reads `Keuangan`, `Tempel angka` and `Buat`; the inputs column reads `TEMPEL ANGKA`, `Uraikan menjadi pos`, `POS`, `Tambah pos`, `PARAMETER (OPSIONAL)` and `Tingkat diskonto %`. The rail rows read `Brief Keuangan`, `Arus Kas & Runway`, `Anggaran vs Realisasi`, `Kelayakan Investasi`, `Cek Kesehatan Rasio`. `finance-studio-empty` has **two** strings and a fresh load shows the second: `Jelaskan brief yang Anda butuhkan.` (`finance.emptyReady`) appears only once a row is confirmed or a dataset is picked; before that it reads `Tambahkan angka, konfirmasikan pos, lalu jelaskan brief-nya.` (`finance.emptyWait`). Confirming a row also flips the panel label to `POS (n)`. Testids are locale-invariant.
- **Cloud live.** Only after doctor `ai`: one generate. Do not screenshot the key.

## Gotchas

- Default desk unlocks Finance. Seeded Legal / Marketing / Students desks do not.
- There are no starters. `finance-starters` and `finance-starter` were deleted on 2026-09-07 in `2394b38` (the 0.14.22 analyst-modes rewrite) and have no successor testid. A map or script that still clicks a starter card is stale — do not file it as a regression.
- **`finance-inputs` is not on every task.** Ratios mounts `finance-ratios-inputs` with `finance-ratios-figures` and `finance-ratios-parse`. A drive that asserts the shared ids across all five fails on ratios only, and that is correct behaviour.
- **There is no coming-soon panel any more.** The component was deleted on 2026-09-17, so `finance-task-coming-soon`, `finance-task-sample` and `finance-coming-soon-back` do not exist in the DOM at all. All five tasks ship, so the one-line `finance-task-unavailable` fallback never renders either and the host's `finance_task_unavailable` 400 is unreachable. A recipe that expects `finance-task-cashflow` to show coming soon is stale.
- **`finance-prompt` is an `<input>`, not a textarea.** Two boxes, two jobs: `finance-figures-input` is the Paste-figures textarea, `finance-prompt` is the one-line brief. A drive that pastes into `finance-figures-input` and clicks Generate does nothing and raises nothing — read the disabled attribute before blaming the gateway.
- **Wait for hydration before pressing `finance-generate`.** It is `type="submit"` in a real `<form>`, so a click that lands before React attaches submits natively: `/finance` reloads and the prompt, the rows and any `finance-error` vanish with nothing raised. Settle after every `goto` / `reload`, or assert `finance-prompt` still holds your text after the click. The general rule is SKILL.md “Harness-wide gotchas” G1.
- **Drafts are per desk and per task.** The prompt and the pasted figures are remembered under `agentforge-finance-draft:<desk>:<task>`; switching task swaps the whole draft and clears the rows, the result and any error. A field that "lost its text" after a task switch is the design.
- A brief with no digit and no currency token skips the parse entirely and lands on the `finance.errors.addItems` message in `finance-error`. Auto-parse never generates in the same click. On an `id` desk that message is `Tambahkan pos terlebih dahulu: tempel angka lalu uraikan, tambah baris secara manual, atau pilih dataset tersimpan.` and **no request is made at all** — verify it by asserting zero `/api/v1/finance/*` calls, which is what separates this branch from the auto-parse one.
- **The parse barely uses the model now.** For text the host can read as a table it asks one labels-only question — what category is this label — and never sees an amount; only text with no table falls through to the old figures prompt. A drive that expects every parse to make a model call will see none on a clean import.
- **The upload never becomes a line item on its own.** `finance-upload-use` writes text into `finance-figures-input` and stops there. If `finance-items` is still empty after an upload, that is the design — press `finance-parse`.
- **A scanned PDF is refused locally.** `finance-upload-error` says OCR is not available on this machine and that nothing was sent anywhere. That is the product working; nothing in Finance's file reading opens a socket.
- **Personal identifiers are redacted before anything leaves.** A name column comes back as `Karyawan 1`, `Karyawan 2`; NIK, NPWP, account, phone and email columns come back masked. `finance-upload-pii` and `finance-result-pii` report the count. A figure that redaction would have eaten is put back and reported as a warning — so an amount that survives in a column headed `2024` is the safety net working, not a missed hit.
- Counts are dropped on purpose. A currency-free whole number under 1000 sitting next to a countable noun — outlets, stores, branches, employees, staff, headcount, units, months, weeks, days, customers, users — is silently removed and never becomes a line item, so "12 outlets" simply vanishes. The same number survives when it carries a currency token and is at or above 1000 ("units sold 12000 IDR"). Expect operational counts to disappear; that is the parser working, not a bug.
- Magnitude suffixes are expanded before the model sees the text. Shorthand the owner types — "IDR 18.4B", "Rp 18,4 M", "5jt", "3 miliar", "900k" — is rewritten to a plain integer. `M` is locale-dependent: million in English, **miliar (1e9)** in Indonesian, decided by the run locale and not by the text. Verifier guidance: do **not** check the margins — they are ratios and stay correct even when the amount is 1e9 too small. Check a stored line-item **amount**: after "revenue IDR 18.4B" the row must read 18 400 000 000, not 18.4.
- **An invented figure is removed, not shown.** The guard marks it, one rewrite is asked for, and whatever still does not trace has its sentence taken out with a note in the report's flags. `[unverified figure]` reaching an export or the screen is a bug to file, not the guard working.
- **A section rewrite no longer mints a second knowledge card.** Regenerate now carries the artifact id back, so `finance-send-kb` after a rewrite updates the same row. A drive that expects two rows is testing old behaviour.
- The studio-header button is `finance-export` (POSTs `/api/v1/finance/export`); `finance-download` is the Markdown button on the shared artifact bar (`${testIdPrefix}-download`, prefix `finance`). `finance-download-docx` is **gone** — it was the DOCX button until the export menu replaced it, and `/api/v1/finance/docx` survives only as an unused alias route. A script or map that still clicks `finance-download-docx` is stale; do not file it as a regression.
- **Export formats are one route, not three.** All of Excel, PowerPoint and Word come out of `POST /api/v1/finance/export` with a different `format`; `pdf` is registered but answers **501** `format_unavailable` on purpose. Assert the content type, not the route.
- **An export by `artifactId` alone can be prose.** The studio always sends the report or the brief it holds, so a drive through the UI gets the full workbook. A drive that POSTs only an `artifactId` gets tables and charts **only** if that run's report or brief was stored on the artifact, and only under the 256 KB meta cap; older or oversized artifacts fall back to their markdown. Do not read a sparse workbook from an old artifact id as a renderer bug.
- **Three things pick the Finance model, and the dropdown is only the first.** `resolveModel` takes `finance-studio-model`, else the desk's saved `settings.documentGenModel`, else the mode default. So two desks on the same build can run Finance on different models with the dropdown untouched — check `GET /api/v1/models` (`defaults.finance`) and the desk's settings before blaming a model for a Finance result. On this gateway the default resolves to `deepseek-v4-flash`. If a different model answered, `finance-result-model-fallback` says so.
- A live brief on the default job model goes quiet for a long time and that is the model thinking, not a stall. The desk default is `deepseek-v4-flash` (the `hy3` first choice is not on the gateway), and DeepSeek V4 thinks before it answers; its reasoning arrives as `reasoning_content`, which AI SDK 4 drops, so the host sees no stream events at all while the model works. DeepSeek V4, GLM-5.3, Kimi K3 and Qwen3.8-Max get the reasoning budgets (240 s to the first token, 180 s idle after it), so a one-to-two minute silence in the drafting phase is expected; only a longer one is a fail. Documents and Market resolve to the same default.
