# Knowledge

Knowledge is an Account-rail page (like Usage), not a `PRODUCT_MODES` id. Soul, pinned Memory, and Sources persist in workspace SQLite. The owner picks Embedding / Brain / Verifier models. Chat injects soul + pinned memories + RAG-retrieved chunks (vectors with FTS fallback). Map reviews the desk; stub map is valid. Sources also fill themselves: every finished Chat turn or job writes a text work card (see [knowledge-ingest.md](./knowledge-ingest.md)); the Sources tab shows that cycle as `knowledge-loop`. See [`docs/internal/maps/knowledge-base-page.md`](../../../../docs/internal/maps/knowledge-base-page.md) for how the page itself works (routes, the one `reload()`, the loop maths, the graph fetch, and what Chat does with Soul / Memory / Sources), and [`docs/internal/maps/knowledge-ingest-loop.md`](../../../../docs/internal/maps/knowledge-ingest-loop.md) for the ingest pipeline behind it.

## Sub-features

- `knowledge-rail` reaches `/knowledge` from `mode-knowledge` on every desk (Account group).
- `knowledge-tabs` switches Sources / Soul / Memory / Map (`knowledge-tab-sources`, `knowledge-tab-soul`, `knowledge-tab-memory`, `knowledge-tab-map`). Tab bodies carry their own testids: `knowledge-sources`, `knowledge-soul`, `knowledge-memory`, `knowledge-map-panel`.
- `knowledge-models` wraps Embedding / Brain / Verifier pickers (`knowledge-model-embedding`, `knowledge-model-brain`, `knowledge-model-verifier`) on every tab. Embedding is a flat Embeddings `<select>` (chat hide-lists must not strip those ids). Change persists via PUT models (seed from GET knowledge.models, else catalog defaults).
- `knowledge-url` + `knowledge-add-url` indexes an HTTPS URL. `file://` fails.
- `knowledge-paste` + `knowledge-add-paste` indexes pasted text under the fixed localized name `knowledge.sources.pastedName` — there is no name field (`apps/web/components/knowledge-page.tsx:251-270`). `knowledge-file` uploads every type the host indexes — `.txt .md .csv .json .html .htm .pdf .docx .doc .rtf .epub .pptx .ppt .xlsx .xls .odt .ods .odp` — from one constant (`KNOWLEDGE_UPLOAD_ACCEPT`, `apps/web/lib/knowledge-upload.ts`); `knowledge-file-formats` under the button prints the same list.
- `knowledge-source-row` shows type tag (`knowledge-source-type`), chunk count, and Indexed or Failed (never a fake Indexed; Failed carries the reason on hover). Types are `File` / `URL` / `Paste` for manual adds and `Chat` / `Documents` / `Research` / `Finance` / `Data` / `Images` / `Videos` / `Presentation` / `Edit` for auto cards. `Legal` is a tenth auto type on the host (`packages/host/src/knowledge.ts:485-496`) that the loop chart does not know: `apps/web/lib/knowledge-loop.ts:18-28` omits it, so a Legal card lands in `knowledge-loop-manual` (the Added-by-hand tile) and sorts after the other work types in the `By type` line. Open bug — do not read it as stray data.
- `knowledge-loop` (Sources tab, above Add a source) is the **Knowledge health** strip that replaced the six-box pipeline drawing on 2026-09-17. Four stat tiles — Work cards / Added by hand / Indexed / Retrieved — sit inside `knowledge-loop-summary`; each tile root still carries the loop stage it became (`knowledge-loop-stage-Work`, `-Saved`, `-Indexed`, `-Retrieved`, each with `data-value` and `data-state`) and each headline number carries the counter testid (`knowledge-loop-work`, `-manual`, `-indexed`, `-retrieved`). `knowledge-loop-chunks` moved to the Indexed tile's sub-line; the **Saved total** lives on the Added-by-hand tile — its `data-value` and its "of N saved" sub-line — while the tile's own number is the manual count. `knowledge-loop-failed` is a red fifth tile rendered **only when something failed**: a healthy desk has no Failed counter at all. One muted `By type` line (`knowledge-loop-counts`, each type a `knowledge-loop-count-<Type>` span with `data-count`) replaced the per-type AUTO bars and renders **only when two or more source types exist** — on a single-type desk read the tiles instead. With no sources it shows `knowledge-loop-empty`. Source counts come from the same Sources list; Retrieved / Verified come from `GET /api/v1/knowledge` (`retrievals`, `verified`). **Removed with the drawing:** `knowledge-loop-cycle` (the pipeline SVG) and `knowledge-loop-stage-Graph` — the graph size now lives only on the map header (`knowledge-graph-counts`).
- `knowledge-loop-verify` ("Run self-check", a ghost button at the top right of the strip) POSTs `/api/v1/knowledge/verify` — a planted-fact check on the host — then reloads the page data, so the status pill flips to `pass` / `fail` with the time and shows the reason on hover. The pill is `knowledge-loop-stage-Verified` (`data-value`, `data-state`) wrapping `knowledge-loop-verified` (`data-state`, plus a new `data-tone` of `pass` / `stale` / `fail` / `never` that drives the dot: green on a pass under 24 h, red on a fail, warm-muted for never-checked or older than 24 h). A failure shows `knowledge-loop-verify-error`.
- `knowledge-graph-panel` (under the health strip) is the **Knowledge map**, collapsed by default. `knowledge-graph-toggle` reads `Show map · N nodes · M edges`; the counts chip inside that button is `knowledge-graph-counts` (`data-nodes` / `data-edges`). Opening it fetches `/api/v1/knowledge/graph?limit=200`: `knowledge-graph-loading`, then legend chips (`knowledge-graph-legend` — node kinds keep their colour dot, the three edge kinds share one muted line swatch) and `knowledge-graph-svg` with `knowledge-graph-node-<id>` in three columns (topics left, sources middle, threads right). Labels sit beside the dot (right-aligned left column, left-aligned right column, centred below in the middle), are cut to 18 characters with the full text in the node's `<title>`, and never overlap: rows are spaced from the column height and never closer than 28px, so a tall graph grows the SVG. Every edge is one thin muted line (`color-mix` of `--text` at 25%); the kind is named in the legend and in the line's hover title only. Only the first **30** nodes are drawn — past that `knowledge-graph-show-all-nodes` ("Show all N") draws the rest up to 200. `knowledge-graph-shown` survives as a header chip carrying `data-shown` / `data-total`; its text reads `around <label>` while focused, `N drawn` while capped, and is **empty** when the drawing already is the whole graph (the old "Showing N of M nodes" sentence is gone). No graph yet → `knowledge-graph-empty`; a broken fetch → `knowledge-graph-error` + `knowledge-graph-retry`. Clicking a node filters to its ego neighbourhood (`knowledge-graph-clear-focus`, "Show all", restores).
- `knowledge-soul-name` / `knowledge-soul-role` / `knowledge-soul-voice` + `knowledge-soul-save` persist the soul.
- `knowledge-memory-input` + `knowledge-memory-add` pins a memory (`knowledge-memory-row`).
- `knowledge-map-run` ("Map knowledge") builds a map; result under `knowledge-map`: a map-level Ready / Not ready tag beside a live / stub tag, an overview, then one topic per entry carrying a **verdict** tag (`supported` / `weak` / `unsupported` / `stub`, `apps/web/components/knowledge-page.tsx:599-616`), and gaps. Stub map is a valid proof — every topic then reads `stub`. Overview, topic summary and topic note are markdown (`FormattedText`).
- Chat send injects that knowledge. Stub Chat still replies. Context popover (`chat-context` → `chat-context-breakdown`) lists Soul / Memories / Sources; Sources reads `<k> chunks · hybrid` when both engines answered (`· rag` vector-only, `· fts` keyword-only, `· none`). Each injected chunk is rendered `[n] <source name>` so a reply can cite it, and every injected chunk is recorded in `knowledge_retrievals` — `GET /api/v1/knowledge` reports the running total as `retrievals`.

## How to get to it (user POV)

- Choose Knowledge Base on the Account rail (`mode-knowledge`).
- Open `http://127.0.0.1:3000/knowledge`.

## Driving it with the DPSBuddy harness

Preconditions:

- Doctor exits 0.
- `mode-knowledge` is visible even on a Legal desk.

- **Open Knowledge.** Click `mode-knowledge`. URL matches `/knowledge`. `knowledge-page`, `knowledge-tabs`, and `knowledge-models` are visible. Model pickers (`knowledge-model-embedding`, `knowledge-model-brain`, `knowledge-model-verifier`) are present.
- **Sources.** `knowledge-sources` and `knowledge-loop` are visible. Paste notes in `knowledge-paste`. Click `knowledge-add-paste`. A `knowledge-source-row` shows Indexed plus a `Paste` type tag / chunk count, and `knowledge-loop-count-Paste` appears (or its `data-count` grows). A fresh desk that already had a Chat send shows a `Chat` row too — that is the ingest loop, not stray data.
- **Soul.** Click `knowledge-tab-soul`. Change `knowledge-soul-name`. Click `knowledge-soul-save`. Reload still shows the name.
- **Memory.** Click `knowledge-tab-memory`. Fill `knowledge-memory-input`. Click `knowledge-memory-add`. A pinned `knowledge-memory-row` appears.
- **Map.** Click `knowledge-tab-map`. `knowledge-map-panel` is visible. Click `knowledge-map-run` ("Petakan pengetahuan" on an `id` desk). `knowledge-map` appears with a Ready / Not ready tag, a stub / live tag, an overview, one topic per source with a verdict tag, and gaps. Stub is fine. **Note:** Map re-embeds every chunk in the workspace first (`packages/host/src/knowledge-map.ts:103`), so the click is slow on a large desk and slower still right after the embedding model was changed.
- **Chat inject (planted fact).** This is the retrieval proof; do not settle for "Sources is listed".
  1. On the Sources tab paste a note containing a token that exists nowhere else — body `The internal code name is zorblatt7731.` Click `knowledge-add-paste`; the row is `Indexed` with `chunks 1`. **You cannot name it from the page**: `knowledge-add-paste` always sends the localized `knowledge.sources.pastedName` ("Pasted notes" / "Catatan tempelan"), so every pasted source on a desk shares one name — and so does its `[n] <name>` citation marker. Pick the row by its chunk count and position, not by name, and expect the reply's marker to read `[1] Pasted notes`.
  2. Open Chat in a **new thread** (a thread never retrieves its own card) and ask `What is the internal code name?`.
  3. Click `chat-context`. `chat-context-breakdown` → Sources reads `1 chunks · fts` (or `· rag` when vectors answer first). `0 chunks` here means retrieval did not fire — that is a fail, not a stub quirk.
  4. The reply names the source: the injected block is `[1] Pasted notes`, so a citing answer says `[1]` / `Pasted notes`. A stub reply that ignores the fact is acceptable only if step 3 showed `1 chunks`.
  5. `GET /api/v1/knowledge` now reports `retrievals >= 1` (webdev doctor surfaces it as `knowledgeRetrievals`). It counts one row per injected chunk per completed run, so it only grows after the turn finishes.
- **Locale (id).** With the desk on `id` (see [locale.md](./locale.md)), this view reads `Basis Pengetahuan`, the tabs `Sumber` / `Jiwa` / `Memori` / `Peta`, and — with nothing indexed — `Belum ada yang terindeks. Kirim pesan Chat atau jalankan mode kerja, lalu kartu muncul di sini.`. Testids are locale-invariant.
- **Health strip and Knowledge map.** Do this after the planted-fact recipe, so the counters have something to show.
  1. On the Sources tab `knowledge-loop-summary` holds four tiles: `knowledge-loop-stage-Work`, `-Saved`, `-Indexed`, `-Retrieved`, each with `data-value` and `data-state`. `knowledge-loop-stage-Retrieved` `data-value` matches the `retrievals` total from step 5 above, and `knowledge-loop-chunks` (the Indexed sub-line) carries the chunk total. There is no `knowledge-loop-stage-Graph` and no `knowledge-loop-cycle` any more — do not wait for them.
  2. Click `knowledge-loop-verify` ("Run self-check"). While it runs the button reads `Checking…`. When it lands the pill reads `Verified · pass · just now`, `knowledge-loop-stage-Verified` carries `data-state="ok"`, `knowledge-loop-verified` carries `data-tone="pass"` and a green dot, and hovering shows the host's detail line. A `fail` is a real result, not a harness error — read the detail before retrying.
  3. Click `knowledge-tab-map` → `knowledge-map-run` ("Map knowledge"), then go back to `knowledge-tab-sources` **and reload the page**. `knowledge-graph-counts` `data-nodes` is now > 0 and `data-edges` counts edges. A stub map counts too. Without the reload the header still reads the pre-map numbers: `runMap` never re-reads `GET /api/v1/knowledge` (`apps/web/components/knowledge-page.tsx:211-230`). Opening the map is the exception — the panel's own fetch corrects `knowledge-graph-counts` upward (`apps/web/components/knowledge-graph-panel.tsx:80-90`), so the closed header and the open one legitimately disagree until something reloads.
  4. Click `knowledge-graph-toggle` ("Show map · N nodes · M edges"). `knowledge-graph-legend` chips appear above `knowledge-graph-svg`, which draws topics on the left, sources in the middle, threads on the right, each label beside its dot and truncated to 18 characters (hover a node for the full label). With 30 nodes or fewer `knowledge-graph-shown` is present but empty; past 30 it reads `N drawn` and `knowledge-graph-show-all-nodes` appears — click it to draw the rest (still capped at 200).
  5. Click any `knowledge-graph-node-*`.

## Gotchas

- Knowledge is not a workspace mode checkbox. Hiding Finance/Data must not hide Knowledge.
- Extract handles text-like files (.txt/.md/.csv/.json), text-layer PDFs, and .docx. A PDF with a text layer and a Word file both reach `Indexed` with `chunks > 0`; PDF text keeps `<!-- page N -->` markers, so a chunk may start with one.
- A scanned (image-only) PDF is the failure case: it comes back 400 `pdf_no_text_layer` — "This PDF has no text layer (scanned image). OCR is not supported yet." No OCR in this build.
- PDF caps: 25 MB (`pdf_too_large`), 20 s (`pdf_timeout`), 500 pages (extra pages are dropped, not an error). Damaged files give `pdf_invalid`; damaged Word files give `docx_invalid`. Anything else (.png, .xlsx, .pptx) is still `unsupported_content_type`.
- URL fetch is HTTPS only, existing TLS rules, size-capped. GET settings still never returns the gateway key.
- Do not POST `/api/v1/knowledge/*` as a substitute for the page on a live proof.
- Only Map triggers a generate; picking models only PUTs the saved ids.
- Pasted / uploaded / URL text goes through the injection guard like auto cards: "Ignore all previous instructions…" pasted into `knowledge-paste` gives a `Failed` row (`injection_blocked`), not `Indexed`. That is correct; the owner bypass in Settings lifts it.
- Offline with a saved key: the first KB write after the gateway goes dark takes ~4 s, then everything is instant for 5 min (local vectors + FTS). Chat fails within ~10 s with "Gateway unreachable"; Settings save within ~8 s. Nothing here needs the internet.
- Work cards never copy files into `data/media/knowledge/`; only `knowledge-file` uploads write there. `addFileSource` stores the original bytes and indexes the extracted text.
- Chat's context popover `Sources` count excludes the current thread's own card (anti-loop). A thread that only has its own card shows `0 chunks` — that is why the planted-fact recipe uses a fresh thread.
- `retrievals` only counts **completed** runs. A run that failed, was aborted, or retrieved nothing adds no rows, so a flat counter after a failed Chat send is correct.
- A Map run does not refresh the closed map header. `knowledge-graph-counts` keeps its pre-map `data-nodes` / `data-edges` until the page reloads (or any other reload-triggering action runs). Reload before reading the graph size. The health strip never showed the graph size after 2026-09-17, so there is nothing stale there to misread.
- Four mutating controls on this page have no testid: the source row's **Remove** (`apps/web/components/knowledge-page.tsx:465-473`), the memory row's **Forget** (`:568-576`), and the Soul rule draft input + **Add rule** button (`:509-527`). Reach Remove / Forget as the last `<button>` inside `knowledge-source-row` / `knowledge-memory-row`, and say in the evidence that you matched the last `<button>` — do not silently `DELETE` the route instead.
- Graph and Verified need a host that reports them. On an older host `GET /api/v1/knowledge` has no `graph` / `verified` fields, so `knowledge-graph-counts` reads `0 nodes · 0 edges`, the Verified pill reads `never` with `data-tone="never"`, `knowledge-graph-panel` shows `knowledge-graph-error` when opened (no `/api/v1/knowledge/graph` route), and `knowledge-loop-verify` fails the same way. That is an old host, not a broken page — the four health tiles still count.
- Webdev doctor reports `knowledge: true` when `GET /api/v1/knowledge` is 200. If `false`, do not treat Chat as broken — skip this feature.
