# Models

The Chat model picker lists curated models first under **Recommended** (`model-group-recommended`) with per-model `bestFor` hints (`model-best-for`), then brand groups (`GPT`, `Claude`, `Gemini`, …) with no extra testids. There is no Advanced disclosure and no `model-picker-all`. Reasoning ids show a `model-thinking-badge`. Doctor (webdev) probes `GET /api/v1/models` so a drive knows mode keys, chat-list size, and that curation metadata is present. Maps: [`docs/internal/maps/chat-send.md`](../../../../docs/internal/maps/chat-send.md) for the send path and [`docs/internal/maps/model-policy.md`](../../../../docs/internal/maps/model-policy.md) for how each model is called and what happens when a call is refused.

## Sub-features

- `models-doctor` prints `modeKeys`, `chatCount`, and `curation` from webdev doctor. `curation: true` is expected on webdev; `false` is a regression there. Packaged `--desktop` cannot GET models over HTTP — `curation: false` / empty `modeKeys` on that surface is expected, not a fail.
- `models-recommended` shows the Recommended group (`model-group-recommended`) — chat-kind only, `tier: "everyday"`, with `friendlyLabel` and `bestFor` (`model-best-for`) on each row. The UI label is **Recommended**; the catalog tier is still `everyday`. Since 2026-09-30 the group is at most seven models, in this order when the catalogue lists them: GPT 6 Luna, Claude Sonnet 5.5, DeepSeek V4.1 Flash, Gemini 3.5 Flash, GPT 6 Sol, GLM 5.3 Flash, Qwen3.7 Plus (`EVERYDAY_MODEL_IDS`, `packages/core/src/models/gateway-roles.ts:191`). GPT 5.6 Luna and Terra, Claude Sonnet 5 and MiniMax M3 are in their brand groups now, and GPT 6 Astra and Claude Opus 5.5 are the deep-reasoning picks there. The default trigger label is `GPT 6 Luna`. Do not pin the row count: it tracks the catalogue.
- `models-brand-groups` lists the rest under brand headers (`GPT`, `Claude`, `Gemini`, …). Those headers have no testids — scroll or search; do not look for `model-picker-all`. Brand rows still carry `model-best-for` (`apps/web/components/model-picker.tsx:337` is unconditional on group), so a `model-best-for` hit does **not** prove you are inside Recommended — assert `model-group-recommended` for that.
- `models-picker` opens from Chat via `model-picker`; the trigger button shows `friendlyLabel` (not the bare slug) once models load. The trigger wrapper is the class `.model-picker` — `min-width: 9rem; max-width: 18rem` — since 0.15.0 (wrapper at `apps/web/components/model-picker.tsx:436`, rule at `apps/web/app/globals.css:850-855`; 144px floor, 288px cap; it moved from utilities into CSS on 2026-09-29 so the narrow composer layout can release the floor, see [chat.md](./chat.md) "Composer layouts"); `picker-panel.test.ts` asserts the floor (≥ 7rem), not one literal. Driven 2026-09-23: `clientWidth` 142 at 1440px and still 142 at 640px, with `composer-send` visible.
- `models-job-fallback` a **job** mode's model is not always the one that answers. When a call fails with a transport-class error, the host retries once on a stand-in and the result carries a `notice` of `{ code: "model_fallback", from, to }` (`packages/core/src/models/job-fallback.ts:9-21`). Finance is the only desk that renders it today: `finance-result-model-fallback` (`apps/web/components/finance-steps/finance-result-notices.tsx:23`), reading "{from} is unavailable; used {to}". Every other job mode gets the same swap through `collectJobAssistantText` and shows nothing. This is not the Chat picker and there is no testid for it on `/chat`.
- `models-thinking-selfheal` a gateway that refuses the Thinking level is not an error the person sees. When a call fails with a 400 that names `reasoning_effort` (or `thinking`, `effort`) before any token or tool call, the runtime retries **once** with one level less, or with no effort parameter when the model takes none, and remembers what worked for that model, for that tenant, for 30 minutes or until Settings is saved. Chat and every job mode share it (`AiSdkRuntime.stream`, `packages/core/src/runtime/ai-sdk-runtime.ts:530-539`). There is no testid: the proof is an answer where an error used to be, one log line on the host, and the request bodies in the unit tests. A model the policy table (`packages/core/src/models/model-policy.ts:177`) does not know is sent no effort unless one was chosen, and is never in Recommended. Map: [`model-policy.md`](../../../../docs/internal/maps/model-policy.md).
- `models-policy-tools` two dev-only tools keep the policy table honest against the live catalogue: `catalog-diff` (which live chat ids the table knows or calls `UNKNOWN`, how every ranked list fares, prices, what is new since the last run) and `probe` (one tiny raw request per Thinking level for the models the table does not know, with the self-heal off, and a proposed table entry per model for a human to review). Code and tests: `packages/host/eval/models/`; map: [`model-policy.md`](../../../../docs/internal/maps/model-policy.md) § 6. They never ship, never call `:3000`, and never edit `model-policy.ts`. There is no testid: the proof is the printed report and the trace under `packages/host/eval/models/results/`.
- `models-recommendation-lists` the order of every list the product ranks by (the Chat default and Recommended set, each job mode's default, the outage stand-ins, the video picker) is data in five files under `packages/core/src/models/`, written down in [`model-policy.md`](../../../../docs/internal/maps/model-policy.md) § 7 and, with prices and the probe that chose them, in `docs/internal/gateway-model-selection.md` § 10. The image, video and audio ids that no role line describes say **Image**, **Video** or **Audio** in their `model-best-for` hint, not General chat. There is no testid for a list: the proof is the printed report and the picker.
- `models-thinking-sent-when-picked` Chat posts `thinking` and `reasoningEffort` only after the person has picked a Thinking level (or restored one they picked before); an untouched picker posts `{ content, model }`. The picker's own look and value are unchanged (`reasoning-effort` shows `medium` / Normal). Code: `apps/web/lib/chat-thinking.ts`; the proof is the request body in the browser's network log, not the DOM.
- `models-picker-panel` is `model-picker-panel` — the list itself (`apps/web/components/model-picker.tsx:376`, trigger at `:440`), portalled with `createPortal(…, document.body)` as `fixed z-[80]` and positioned by `placePickerPanel` (`apps/web/lib/picker-panel.ts`). Inside it only `model-group-recommended` (Recommended group only), `model-best-for`, and `model-thinking-badge` are testids; there is no search-box testid and no per-option testid — rows are `[role="option"]`. `reasoning-effort` is a **sibling** control in `chat-composer.tsx`, not part of the picker. Portal mechanics and narrow-pane rules live in [chat.md](./chat.md) — `chat-model-switch`.

## How to get to it (user POV)

- Open `http://127.0.0.1:3000/chat`.
- Click the model control (`model-picker`) in the composer toolbar (`composer-toolbar`). The button shows the selected model's friendly label.
- Scroll or search past Recommended to reach a brand-group model.

## Driving it with the Nultron harness

Preconditions:

- Doctor exits 0 against `http://127.0.0.1:3000` (webdev).
- Record `modeKeys`, `chatCount`, and `curation` from the doctor JSON. Expect `curation: true` on webdev.

- **Doctor models.** Confirm the report includes `modeKeys` (array), `chatCount` (number), and `curation: true`. `curation: false` on **webdev** is a fail (catalog missing `friendlyLabel` / `bestFor` / `tier`). Non-200 on `GET /api/v1/models` is a doctor fail. Models in the payload carry `friendlyLabel`, `bestFor`, and `tier` (`"everyday"` | `"advanced"`).
- **Open picker.** Go to `/chat`. Click `model-picker`. The trigger is visible and shows a friendly label — not the bare word `Model` alone after models load.
- **Recommended + bestFor.** Assert `model-group-recommended` is visible. At least one `model-best-for` hint is present on Recommended rows.
- **The lists of 2026-09-30.** Offline, exact: `npx pnpm@9.15.9 --filter @agentforge/host eval:models:diff --refresh --no-save` (a read of the gateway's list and its public price list; nothing is written) prints every list with `LIVE` or `MISSING`, and on 2026-09-30 every chat id in every list was live (0 missing; video 2 live of 7, image 1 live of 3, because the gateway lists `seedance-2.0`, `seedance-2.5` and `gpt-image-2` and none of the older ids). In the picker on a desk that lists them: the trigger reads `GPT 6 Luna`, Recommended shows the seven above in that order, Luna's hint says Fast drafts, Sol's and Sonnet 5.5's say Everyday chat, and an image or video option in a studio picker ends in Image or Video. Not driven in a browser: the `:3000` host needs a restart.
- **Brand groups.** After Recommended, brand-group rows exist. Search can surface a non-recommended id. Do not assert `model-picker-all`.
- **Escape after a mouse open.** Click `model-picker` (a real click, not Ctrl+K). `model-picker-panel` opens and `document.activeElement` is the search box (`INPUT`, `role="combobox"`). Press Escape. Proof: `model-picker-panel` is gone, `model-picker` has `aria-expanded="false"`, and `document.activeElement` is `model-picker`. Then Ctrl+K → focus in the search box → Escape → panel gone and focus on `composer-text` (the keyboard path returns to the composer, not the trigger). Driven 2026-09-23 on webdev: both paths as described.
- **Switch a model.** Click `model-picker`; `model-picker-panel` opens outside the composer toolbar row. Click an option that carries **no** check mark. Proof is the trigger label becoming that model's `friendlyLabel` — not the panel closing. Driven 2026-09-17 at 1280×800 (`chatCount: 110`): trigger `GPT 5.6 Luna` → `Claude Sonnet 5`, trigger `clientWidth` 142px (box 144), `model-picker-panel` box x=409 y=379 w=352 h=344 (flipped above the trigger, clear of the toolbar row), **101** `[role="option"]` rows, panel gone after select. The panel width (352) and height (344) are stable across viewports; x/y are not — assert the box does not overlap the toolbar row, not fixed coordinates. Option count tracks the catalog and drifts; do not pin it.
- **IDE proof.** Screenshot of the open picker under `evidence/models/<run-id>/` with Recommended group, a `bestFor` hint, and Chat identity visible.
- **Cloud.** Doctor JSON must report `curation: true`. Picker UI smoke asserts `model-group-recommended` and `model-best-for` as real testids.
- **Driving the Thinking self-heal.** The retry is a host and runtime behaviour, so the browser cannot show it and a stub gateway never refuses anything. Two proofs, in this order.
  1. **Offline, exact (this is the proof that exists).** From `packages/core`: `npx vitest run src/runtime/ai-sdk-runtime-effort.test.ts src/runtime/ai-sdk-runtime-wire.test.ts src/models/model-policy.test.ts src/models/model-policy-guard.test.ts`. The first runs the real runtime and AI SDK against a stub `fetch` that answers 400 with `Unsupported value: 'ultra' for reasoning_effort` and then a stream: request 1 carries `reasoning_effort: "ultra"`, request 2 `"max"`, a third call goes straight to `"max"`, and a reset (what saving Settings does) sends `"ultra"` again. It also shows the cases that must **not** retry: context length, a bad key, a missing model, a second refusal, and a request after a tool ran. The second replays 260 recorded requests for known models and needs every byte unchanged. Passed 2026-09-30.
  2. **Live on `:3000` (not driven).** Needs a chat model the gateway lists that the table does not know, and a host restarted onto this code (`tsx server.ts` has no watcher; say "restart :3000", never do it). In `/chat` pick that model, **pick** a Thinking level of **Extra**, **Max** or **Ultra** (`reasoning-effort`; the level is only sent once it is picked, see the gotcha below), send. Expect an answer, and expect **no** `composer-error`. Its snap is silent (an unknown model tops out at Deep), so the host log shows nothing for a normal send. Only when the gateway itself refuses a level does the host print one line, `gateway: effort limit learned model=<id> requested=<level> learned=<level>` (preceded by the older `gateway: HTTP 400 …` line for the refused request). Send again with the same level: the `gateway: effort` line does **not** repeat and no second `HTTP 400` appears, because the next call starts from the learned level. Save Settings (any save; Start over is not needed and is destructive on the shared instance) and repeat: the refusal, the retry and the line come back.

## Gotchas

- `curation: false` on webdev is a regression now that Phase 1 curation ships on `/api/v1/models`. Do not soft-pass it. On `--desktop`, `curation: false` is the doctor limit (no HTTP models probe).
- The Chat list is chat-kind only. Image/video model pickers on Generate surfaces are separate features. Documents / Research / Presentation generate bars use `*-studio-model` (`model-select.tsx`). Section/slide regen uses `*-regen-model` on the regen panel. Knowledge embedding uses a flat `Embeddings` group when `flat`.
- `model-group-recommended` and `model-best-for` are real — assert them. `model-picker-all` was removed; do not invent it.
- Doctor `chatCount` (110 on 2026-09-17) is the chat-kind model count from `/api/v1/models`; the picker rendered 101 rows. They are allowed to differ — do not assert equality.
- The Recommended group's **visible** header is locale copy (`Disarankan` on an `id` desk). `model-group-recommended` is the handle; the brand headers (`GPT`, `Claude`, …) are brand names and stay untranslated.
- **The native `<select>` pickers say it too (2026-09-29).** The studios and Knowledge use `ModelSelect` (`<optgroup label=…>`), which used to show English literals ("Recommended", "Other", "Embeddings") on an `id` desk. Core now sends each group with a stable `kind` (`recommended | brand | other`) and the renderer translates through `pickerGroupLabel` (`apps/web/lib/picker-group-label.ts`, keys `chat.models.groups.recommended|other|embeddings`): on `id` the optgroup labels read `Disarankan`, `Lainnya` and, for the Knowledge embedding picker, `Embedding`. Check with `[...select.querySelectorAll("optgroup")].map(g => g.label)` on `documents-studio-model` or `knowledge-models`. Test: `apps/web/lib/picker-group-label.test.tsx`.
- **Doctor `modeKeys` shrank (2026-09-29).** `GET /api/v1/models` sends the chat catalogue once, as `models`; `modes` now carries only the lists that differ (`image`, `video`, `audio`, `other`, `music`, `embedding`), so `modeKeys` no longer lists `chat`, `documents`, `market` and the other chat-shaped modes. `chatCount` still counts `models`. Do not assert a chat-shaped mode key.
- Settings / studio / Knowledge `<select>` paths (`model-select.tsx`) use **Recommended + brand** optgroups (`GPT`, `Claude`, …) with `friendlyLabel — bestFor` option text, not Everyday / Advanced optgroups. Chat uses the palette above.
- The currently-selected option's text is prefixed with a check mark (`U+2713`). A driver that picks “the first option whose label differs from the trigger label” therefore re-picks the current model and proves nothing. Pick an option that carries no check mark.
- `model-picker-panel` closes on an outside mousedown and on selecting an option (a mouse click on `[role="option"]` changed the trigger from `GPT 5.6 Luna` to `Qwen3.7 Plus` and closed the panel, driven 2026-09-23). **Escape closes it however it was opened.** The panel only mounts once `pos` is set, one commit after `open`, so the search box takes focus in an effect keyed on `isPanelMounted(open, pos)` (`model-picker.tsx:104`, `:263-268`), not at click time; the trigger also handles Escape while open (`onTriggerKeyDown`, `:297-302`). Escape returns focus to whatever opened the palette (`focusAfterClose`, `:89`): `model-picker` after a click, `composer-text` after Ctrl+K. Picking a model always returns to the composer. Until 2026-09-23 a mouse open left focus on the trigger and Escape did nothing (0.15.0 verify finding 3); a recipe that clicks outside to close is still valid but no longer needed. Unit proof: `apps/web/lib/model-picker.test.tsx` (node, no DOM — the focus sequence itself is only proven by driving). Scrolling **re-places** the panel; it does not close it.
- **A job mode that answers on a different model than the picker shows is not a bug.** `runWithJobModelFallback` (`packages/host/src/job-model-fallback.ts:160-186`) swaps **once** and only on a transport-class failure — 502/503/504, `unavailable`, `ECONNREFUSED`, `fetch failed`, the response-header abort and the stream watchdog (`GATEWAY_UNAVAILABLE`, `packages/core/src/models/job-fallback.ts:45-46`). A 400/401/403/404/422/429, a bad key, an unknown model, a context-length error, a content filter or "returned no text" is **never** swapped (`NOT_A_TRANSPORT_FAILURE`, `:57-58`). Two more hard stops: a model the person picked themselves in the studio bar is never swapped (`modelExplicit`), and neither is a call that had already started streaming — a half-written answer is not re-run (`maySwapModel`, `job-model-fallback.ts:139-147`). If the stand-in also fails, the original error is rethrown untouched, status and all.
- **The stand-in comes from a per-mode list, then a shared tail.** `JOB_MODE_PREFERENCES[mode]` (`packages/core/src/models/mode-defaults.ts:64-83`) followed by `JOB_FALLBACK_TAIL = ["gpt-6-luna", "claude-sonnet-5-5", "gpt-5.6-luna", "deepseek-v4-1-flash"]` (`packages/core/src/models/job-fallback.ts:38`; the list before 2026-09-30 was `gpt-5.6-luna`, `claude-sonnet-5`, `gpt-5.6-sol`, `kimi-k3`), filtered to ids actually live in this desk's catalog and deduped. A mode the host was given no name for gets the tail only. Do not pin the chosen id in a recipe — it tracks the catalog.
- **A failed model is skipped for five minutes afterwards.** `JOB_MODEL_DOWN_MS = 5 * 60 * 1000` (`packages/host/src/job-model-fallback.ts:26`); `startModel` (`:132-137`) skips a model still marked down before the *first* attempt, so a second job can land on the stand-in with no failure of its own. Saving Settings or signing out clears that breaker and the learned Thinking-level limits with it (`resetModelReliabilityState`, `packages/host/src/job-model-fallback.ts:66`, called at `packages/host/src/handlers/settings.ts:259` and `:417`) — so re-save the key before concluding a model is unreachable.
- **A 400 is still never a model swap.** The Thinking self-heal sits below `runWithJobModelFallback`: a job that heals never reaches it, and a 400 that does reach it (`NOT_A_TRANSPORT_FAILURE`) is rethrown as before. Do not read a healed job's answer as a `notice`; there is none, the model did not change.
- **From Chat, the level is sent only once it was picked (since 2026-09-30).** The picker shows Normal from the start, but the composer posts `thinking` and `reasoningEffort` only after the person has picked a level or restored one they picked before (`thinkingRequestFields`, `apps/web/lib/chat-thinking.ts:67`; wired at `chat-composer.tsx:415`, `:481`, state in `chat-session.tsx:68`, `:73`). So on a **fresh browser profile** the first send to an unknown model carries no `reasoning_effort`, and after you touch the picker (even to pick Normal again) it carries the level, capped at Deep; a known model gets `medium` either way, unchanged. To drive the unknown-model case, clear `localStorage` (`agentforge-chat-reasoning-effort`, `agentforge-chat-thinking`) first, or pick a level on purpose; jobs send nothing. Not driven in a browser.
- **GPT-6 now carries its level on Responses (since 2026-09-30).** A GPT-6 Responses request has `reasoning: { effort, summary: "auto" }` at every level the table allows; before this the SDK dropped it. Off floors to `low` for GPT 6 Astra and any GPT 6 id without an entry of its own, and is `reasoning: { effort: "none" }` (no summary) for `gpt-6-luna` and `gpt-6-sol` since 2026-09-30, which the probe's raw requests took and no request built by this runtime has yet met the live gateway. Live effect not driven: if the gateway answers 400 to it the self-heal drops the block for 30 minutes, which is the old behaviour at the cost of one refused call.
- **The notice is not an SSE event.** It rides the final JSON result, not `job.*`, so a driver watching the stream will not see it. Read `result.notice` — or the `finance-result-model-fallback` line — after the job returns.
- Do not restate the portal story here. The toolbar wrap rule, the ≥110px trigger floor, the 480px rail caveat, and the Playwright-calls-a-clipped-option-visible trap are in [chat.md](./chat.md) — the `chat-model-switch` bullet and its Gotchas.
- Doctor must hit loopback only. Packaged: use `--desktop`, never treat :3000 as the installed app.
