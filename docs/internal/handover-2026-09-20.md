because `xlsx` is fetched from `cdn.sheetjs.com`, which the container's network policy denies. So
`.cursor/skills/verify-agentforge/scripts/doctor.mjs` has nothing to talk to, and the pstack verifier and mapper
half of that skill lives in the Cursor plugin, not in this repo. What the cloud can do is read every `file:line`
claim against the tree, run the map-rot grep over `.cursor/skills/`, and check every relative link resolves. What
only Kyo can do is drive `127.0.0.1:3000` and run the pstack mapper. The `playwright` check on GitHub Actions is
red on every run in this repository's history, including on `main`, because of an Actions billing lock on the
account; it dies in a few seconds before any test body runs and is not a signal about any branch.

the code has been on `main` since PR #56 (`6ae177a`). The migration plan labelled Phase 1 and Phase 2 as "landed on

tenancy docs disagreed about when the gateway key reset gets scoped to a tenant: the Phase 3 spec said Phase 3, the
migration plan said Phase 4, so whoever picked up Lane D would have had to guess.

- `docs/internal/web-pivot-2026-09-18.md` — open decision 3 is now **Status: landed**, pointing at PR #56 and
  naming the functions that implement it. The architecture snapshot marks `isAllowedMutatingApiRequest` as the
  desktop and webdev path, superseded in server mode.
- `docs/internal/web-migration-plan.md` — Phase 1 and Phase 2 say merged. Phase 3 now owns the
  `clearGatewayKeyEverywhere` scoping and gains a test for it; Phase 4 drops it from its test list and risk and
  keeps the `settings.enc` backend swap as its real risk. The Phase 1 test list no longer claims a
  "token from a different session" case, which the code cannot have yet.

  confirmation, not a conflict; four `web-migration-plan.md:NNN` cross-references re-pointed after the plan grew.
- `docs/internal/web-security-spec.md` — rows A1 and A2 marked landed with the implementing functions, in the
  same style as A9 to A13.
- `docs/internal/maps/settings-and-gateway-gate.md` and `maps/pii-and-key-security.md` — the stale "has to become
  a trusted-origin allowlist ... (open decision 3)" line retired; the `clearGatewayKeyEverywhere` range corrected.

and is not; the `clearGatewayKeyEverywhere` range was wrong in four files; `isAllowedMutatingApiRequest` and
