## Finance is task-based (PR #52, `8c5211b`) — 2026-09-17

Five tasks under the Finance rail entry — **brief, ratios, budget, cash flow, appraisal** — registered in `packages/core/src/finance/tasks.ts` + `tasks/`, with the maths in `packages/core/src/finance/{ratios,budget,cashflow,appraisal}/`. Host pipeline: `packages/host/src/finance-task.ts` → `finance-tasks/runner.ts`. An unknown `?task=` resolves to `brief`, never an error.

**Figures are computed in core, deterministically; the model names categories and writes the narrative, it never produces an amount** — `number-guard.ts`, `stated-facts.ts` and `packages/host/src/finance-section-repair.ts` hold that line. `derived-rows.ts` keeps a sheet's own totals beside the items instead of adding them in twice (a 7 570 000 000 revenue had been reading back as 15 164 000 000); `stated-facts.ts` reads figures an annual report puts in a sentence rather than a table; `register-metrics.ts` covers list-shaped input (payroll, fee schedule, per-outlet sales) under the rule that **columns are never added to each other**. `magnitude.ts`, `figures-text.ts`, `figures-rows.ts`, `period-figures.ts`, `period-metrics.ts`, `trend-metrics.ts`, `line-item-normalise.ts`, `metrics.ts`, `report-formulas.ts`, `report-brief.ts` and `types.ts` were reworked alongside them.

**Files in and out.** `POST /api/v1/finance/import` (25 MB / 30 sheets / 5000 rows, `import-table/limits.ts`) reads a spreadsheet or document into figures; `POST /api/v1/finance/export` renders xlsx, pptx and docx through `packages/host/src/renderers/` (pdf answers 501). The studio's header DOCX button is replaced by one `finance-export` menu that remembers the last format used; `financeArtifactMeta` (`packages/host/src/finance-artifact.ts`) stores the brief JSON + guard summary on the artifact so an export is full-fidelity, falling back to `financeReportFromMarkdown` for briefs saved before it. Uploads mount inside `finance-inputs` and merge into the figures box, so a file still goes through `/finance/parse` and the owner's row confirmation like a paste. The result column moved into `finance-steps/finance-result-panel.tsx` and draws `FinanceReportCharts` above the brief prose.

Maps: [`finance-parse-and-generate.md`](maps/finance-parse-and-generate.md), [`finance-tasks.md`](maps/finance-tasks.md).

## Local file extraction on the machine — no hosted OCR (PR #52, `8c5211b`) — 2026-09-17

`packages/host/src/file-extract` reads pdf / docx / pptx / xlsx / odt / rtf / epub and friends locally through `@firecrawl/anydoc` 0.2.4 (MIT), a napi-rs native module, with a fallback reader behind it. Caps are 25 MB / 20 s, and extension and magic bytes must agree or the file is refused as `format_mismatch`. **No hosted OCR, ever**: a scan is refused locally as `needs_ocr`, and `no-hosted-ocr.test.ts` keeps it that way. Knowledge ingest and Finance import both use it.

If every route fails the app still works: `extractFile` logs once and degrades to pdfjs, JSZip + xmldom and SheetJS; only .pptx / .odt / .rtf / .epub become unreadable.

## First-run component installer — the owner never installs a native dependency (PR #52, `3a598c9`) — 2026-09-17

Owner decision 2026-09-17: nothing may be a manual step the way ffmpeg still is. `packages/host/src/components/` is now the only way the app installs a native dependency, modelled on Hermes' bootstrap: a frozen manifest → stages `check, download, verify, unpack, probe, marker` → `job.phase` / `job.step` events → an atomic completion marker → every stage `skipped` on the next launch. Files land in `<dataDir>/components/<id>/<version>/`.

Two routes, tried in this order by `file-extract/anydoc.ts`:

1. **Bundled.** `apps/desktop/package.json` depends on `@firecrawl/anydoc` (electron-builder only walks the desktop package's own production dependencies) and `asarUnpack` lists `@firecrawl/anydoc` and `@firecrawl/anydoc-*`, so a packed Windows build carries it. No rebuild step — the binaries are prebuilt and ABI-independent.
2. **Downloaded on first run.** Pinned tarballs from `registry.npmjs.org`, sha512 checked before a byte reaches the final directory, a tar reader that refuses absolute paths, `..`, links and oversize archives, atomic promote, completion marker, idempotent. On macOS both routes exist: since `05e97a5` the Docker pack fetches the pinned `anydoc-darwin-<arch>` package per arch (sha512-checked against the same manifest) and ships it in place of the Linux one — the first 0.14.27 mac pack at `e2e477e` failed `verify-bundle` with two ELF binaries inside the `.app` for exactly that reason — and the first-run installer remains the fallback for a build where the bundled copy does not load.

`GET /api/v1/components` reports `ready | missing | installing | failed | unsupported` with `source: bundled | downloaded`; `POST /api/v1/components/install/stream` runs it. Neither is gated — it runs during onboarding, before a key exists. Onboarding renders the panel (`component-setup`) and starts it without a click; an already-onboarded desk runs it silently after the gate opens. A failure never blocks onboarding, because `file-extract` falls back. URLs and sha512 integrity come **only** from `manifest.ts`, never from a request. `auto` is `false` under `AGENTFORGE_RUNTIME=stub` and in tests, so Cloud and Playwright never download. Start over (`scope: "all"`) removes the downloaded copy.

**Two bugs it caught, both of which would have shipped:**

- Inside the esbuild CJS bundle `import.meta` is `{}`, so `createRequire(import.meta.url)` threw and the packaged app would never have loaded the bundled copy — it would have fallen back silently forever. Fixed with the guard `typeof require === "function" ? require : createRequire(import.meta.url)`, now used by every runtime require in host code (`file-extract/anydoc.ts`, `sql-runner.ts`).
- The **probe** stage required the completion marker that is only written after the probe passes, so the first live run failed `probe_failed`. Unit tests with an injected probe had not caught it; one real install into a temp `AGENTFORGE_DATA_DIR` did. Both are now traps in AGENTS.md.

**A new native dependency is a manifest entry, never an instruction to the owner.** ffmpeg is the next candidate and today still shows the manual `ffmpeg-setup-notice`.

Map: [`component-installer.md`](maps/component-installer.md); recipe `features/components.md`.

## PII: eight kinds, including Indonesian identifiers (PR #52, `8c5211b`) — 2026-09-17

`packages/core/src/security/pii-id.ts` (new) adds `scanIndonesianIds` — NIK (BPS province code, real birth date, non-round serial), dotted or labelled NPWP, a bank account only behind a strong cue (`No. Rekening`, `norek`, `a/c`), and `08xx` local phones — and runs **first** inside `scanPii` so a NIK that happens to pass Luhn reads `[nik]` and not `[card]`. `PiiKind` is eight kinds now (`[nik]` `[npwp]` `[account]` `[name]` joining the original four), and because the splice is inside `scanPii` rather than behind a Finance flag, **every** `maskPii` caller gets them — Chat, knowledge cards, studio prompts, research and market queries. `packages/host/src/market/tools.ts` widened `PII_MASK_TOKEN` to all eight so an FTS query cannot carry a literal `[nik]`.

Finance adds the column-aware half, `packages/core/src/finance/pii-scan.ts` + `pii-columns.ts`: a header of `Nama` / `NIK` / `No. Rekening` / `No. HP` / `Email` redacts the whole cell, names becoming stable pseudonyms (`Karyawan 1`, `Karyawan 2`) so per-person rows stay distinguishable and every total still adds up; an amount header outranks every other rule. `packages/host/src/finance-privacy.ts` (`guardFinanceInput`) is wired into every Finance route and all four non-brief tasks.

**Rule: redaction may hide an identifier, never a figure.** `restoreFinanceAmounts` puts any masked amount back, and a 200-amount property table in `pii-scan.test.ts` caught two pre-existing false positives that had been silently rewriting figures (a rupiah total written `1.250.000.000.000` came back `[phone]`).

Map: [`pii-and-key-security.md`](maps/pii-and-key-security.md).

## Job model fallback (PR #52, `8c5211b`) — 2026-09-17

## What is NOT proven at the 0.14.27 cut

Stated plainly, because the PR's own test plan leaves these open and nothing since has closed them. Do not read any of it as done.

- **Packaged bundled-anydoc load.** No packed Windows installer has been shown to load the bundled `@firecrawl/anydoc`. `asarUnpack` and the `typeof require` guard are the reasons to expect it to work; nobody has watched it work. `doctor --desktop` plus `GET /api/v1/components` reporting `source: "bundled"` is the proof owed.
- **Any macOS run.** The download route has never run on a Mac. An ad-hoc-signed, non-notarized app should be allowed to `dlopen` a downloaded `.node`, but that is an expectation, not an observation.
- **The onboarding component panel.** Never seen in a browser or on the packaged app — on this desk anydoc is bundled, so the panel correctly renders nothing.
- **Finance, Market and rail drives on webdev.** Finance tasks, import/export, the Market team run through the current build, the rail submenus and `GET /api/v1/components` have not been driven on `:3000` since the merge. The `:3000` host must be restarted after the host/core edits in this PR before any of it is drivable (`tsx server.ts` has no watcher).
- Nothing in this cut is packed, installed, or driven on the installed app. Playwright `foundation.spec.ts` is owed from GitHub Actions / Cloud.
- ffmpeg is still a manual install on both platforms; it is the next manifest entry, not part of this cut.

Everything that was still open before the 0.14.26 cut and not closed by it — the Legal live matter run, the packaged Windows drive of Start over + the gateway gate, the manual Windows smoke list, the packaged CSP console check — is still open.
