# 0.15.0 — internal changelog

Append-only. Same rule as every 0.14.2x file: nothing here counts as shipped until it is staged (`host.cjs` + renderer), packed (`pnpm desktop:build`), installed, and driven on the packaged app (`doctor --desktop`).

**This cut is the personal Mac/Windows app, not the hosted web offer.** The owner split the two products explicitly on 2026-09-23: **Personal is the Mac and Windows DPSBuddy app; Enterprise is the hosted web app**, contacted through DPS, priced per user. Everything in this file is the personal app. The Phase 9 portal/plans work that was sitting uncommitted in the same tree is deliberately **not** in this cut — it stays on `main`'s working tree for its own pull request.

Version: `0.15` per the owner's ruling of 2026-09-23. The 0.14.2x scheme was scoped to desktop maintenance cuts; this is the first cut that is a product release rather than maintenance, so it takes the next minor. `apps/desktop/package.json` moves `0.14.27` → `0.15.0`.

## What this cut is about

The desk was functional but read as flat, gray and noisy: dark-only by default, Inter at one weight, every mode leading with a paragraph about *how* to use it instead of *what you get*, and controls that had grown a frame inside a frame. This cut is a visual and editorial pass over the whole personal app, plus the bugs the pass exposed.

## 1. A warm, light-first desk

- **Light is the default.** `resolveTheme(null)` returns `"light"` (`apps/web/lib/theme.ts`), and `themeInit` in `apps/web/src/main.tsx` falls back to light, so a boot with no stored preference paints light before React runs. `:root` carries the light values rather than the dark ones.
- **Full white, black text.** `--bg` and `--surface` are `#ffffff`; `--text` is `#0a0a0a`, `--text-2` `#2e2c29`, `--text-3` `#5c574f`. Contrast against white is 19.9:1 / 12.9:1 / 7.0:1, so the muted tier is AA for body text where the previous `#746f67` was borderline. The owner's report was that gray-on-gray was hard to read.
- **A blue float is the product's only shadow.** `--shadow-float`, 38% of `--accent` on light and 26% on dark. `.desk-canvas` became a raised panel over the app backdrop — 8px margin, 4px radius — so the shadow has somewhere to fall. A legacy compat block in `globals.css` was setting `--shadow-float: none` *after* the definition and silently cancelling it; that duplicate is gone.
- **Tight corners.** `--r-nav` / `--r-card` / `--r-pill` are all 4px, down from 12/16/999.
- **The rail follows the theme.** `--rail-*` is defined per theme (`:root`, `.light`, `.dark`). It was briefly dark chrome in both themes to match a mockup; that left the whole left edge behind when switching to light, which is not what "light is always the default, blue and light" means.
- **Outfit + Sora → DM Sans + Source Serif 4**, bundled as woff2 under `apps/web/app/fonts/`. Both are variable fonts, so four physical files cover every weight the UI asks for; the build script is `scripts/fetch-ui-fonts.mjs` and `manifest.json` lists the same file for 400/500/600/700. **No runtime font host** — the app still renders with no internet.
- **The theme toggle is one bordered `<select>`-style row**, and the rail footer is a single aligned row of 32px squares (theme, updates, collapse). Labels live in `aria-label` / `title` so nothing is lost to a screen reader.

## 2. Every mode leads with its outcome

The owner's report: *"too many words, very complicated, i dont even know how to use it"*, and of Finance specifically, *"what is the outcome from finance?"* — which the UI never answered.

**The rule applied to all 12 modes:** header is **title + one outcome line**. The `kicker` div, a redundant `expectedInputs` paragraph and any second `subtitle`/`lede` are gone. The surviving line starts with the deliverable, not the method.

| Mode | The line |
|---|---|
| Finance | You get: a written brief with every core metric — margins, burn, runway, breakeven, NPV — computed in code and traced. |
| Documents | You get: a titled, sectioned draft you can preview and download as a DOCX. |
| Research | You get: a cited dossier — Question, Findings, Sources — you can reopen, download, or send to Documents, Presentation, or the Knowledge Base. |
| Legal | You get an issues memorandum, a tracked-changes redline, a deviation report and a red-flags summary — with every number, quotation and cross-reference checked in code first. |
| Market Watch | You get live prices and a chart per ticker, plus a written briefing — type up to 15 tickers, no file upload. Analysis, not investment advice. |
| Meeting | You get a transcript, structured minutes, and the same minutes in the other language — from a recording or a pasted transcript. |
| Images / Videos / Music | You get: a generated image / clip / finished song, saved to the gallery below. |

**Optional controls moved behind a disclosure**, so four number boxes stop reading as mandatory:

- Finance — "How this works" (the pipeline strip) and "Advanced" (discount rate, fixed costs, price, variable cost)
- Data — "How this works" and "Or paste a table"
- Videos — resolution and the image-to-video still, leaving aspect, seconds, prompt and submit open
- Music — style, title, instrumental, leaving model, lyrics and generate open
- Meeting — the "or paste a transcript" path
- Channels — the standing privacy warning
- Knowledge — the Map tab's model walkthrough

Settings, Usage, Workspaces and Knowledge got **kicker removals and a tightened intro only**. Every control on those pages is intact; the Settings edit-cap field was deliberately not folded because `features/settings.md` drives it.

## 3. Chat: from a wall of prompts to a place to type

- **The empty state was cut to three things** — headline, key status, one line. It had a three-step checklist, three mode cards and a four-tile model strip, which offered the same choice twice and recommended modes the rail already lists as first-class entries.
- **Then it was rebuilt so it teaches.** Four **intent cards** (Shape a plan / Summarise something / Rewrite for a reader / Think a decision through), each a title, a one-line hint and a prompt that fills the composer. They are shaped by *intent*, not by mode, which is what keeps them from duplicating the rail. Clicking fills rather than sends, so the prompt is a starting point you edit.
- **The decoration was removed.** A radial accent bloom and a hairline grid were added and then cut the moment the owner asked "what is this blue accent thing??" — my own addition, not a request.
- **Tool calls moved inside the Thinking disclosure.** They used to sit above the answer, so a finished turn showed the machinery before the prose. The disclosure opens itself while the turn is live and collapses when it lands; a curious user can reopen it. It keys on `thinking || tools`, not `thinking` alone, because a stub run fires tools without emitting reasoning.
- **Tool rows are summarised, not dumped.** `gist()` in `apps/web/lib/tool-labels.ts` reads the shape of a payload: `Past chats · {"action":"list"} → {"success":true,"sessions":[]}` now reads `Past chats · list → none`. Any unrecognised object collapses to a field count instead of raw JSON.
- **Thinking renders as markdown**, not a `<pre>`, so lists, emphasis and fenced code embed properly.
- **The composer is honest and simple.** The duplicate "Type a message to start" hint is gone (the placeholder says it); the Attach control is a 32px icon in the toolbar instead of a large button in the drop zone; and the drop zone is one line, not three.
- **Focus no longer draws a box around the composer.** The 2px `outline` at a 2px offset read as a second rectangle; the composer's own border now turns accent on `:focus-within`.
- **Thinking is one control.** It was a bordered `label` wrapping a bordered `select` — a box inside a box however the padding was tuned. It is a single `<select>` showing just the level (`Normal`, `Off`, `Deep` …), matching the model picker beside it, with `aria-label="Thinking"` kept.

## 4. Bugs the pass exposed

- **The rail footer was invisible.** `.btn` is unlayered CSS and therefore beats `@layer utilities` at equal specificity, so `.btn { color: var(--color-text) }` overrode the rail's own `text-[…]` utility and painted the icons dark-on-dark. Scoped an override to `[data-testid="rail-footer"] .btn-ghost`.
- **Finance and Market were losing their names.** `RailSubmenuToggle` rendered its label ("Show specialists", "Show tasks") *beside* the mode name, squeezing Market to nothing and truncating Finance to "F.". It is arrow-only now; the words survive in `aria-label` / `title`.
- **The left accent stripe on the selected rail row is gone** — decoration on top of the fill that already marks the row as current.
- **"Offline demo" was a lie in three places.** The gate's `stub` status means *no key has been pasted*, not that a demo is running. Chat said "Model key connected (offline demo)" with no key; Settings said "Offline demo" twice. All three now read as what they are, and the `foundation.spec.ts` assertion that pinned the old string was updated.
- **Prompt boxes were invisible in three modes.** Presentation, Documents and Research all used a transparent, borderless `input` inside the form's surface panel. They now use the app's `text-field` recipe — a real border, and an accent border on focus.
- **The Meeting language field had no gap** between its caption and its select; the select was not `w-full`, so the two ran together. Both the title and language fields stack the same way now.
- **The `New` badge on Music and Meeting is gone**, and the whole self-expiring mechanism with it — `NEW_BADGE_UNTIL`, `newBadgeOn()`, the `badge` prop and the `rail.badgeNew` key in both catalogs.
- **`picker-panel.test.ts` was reconciled.** The trigger was changed to `min-w-[9rem] max-w-[18rem]` without updating the test that pinned `min-w-[7rem]`, so the suite was red for a reason nobody could see in the diff. The assertion is now on the *floor* (≥ 7rem) rather than one literal, so tuning the two bounds cannot read as a regression.

## 5. Layout

- **Content lanes replaced one hardcoded cap.** `--content-narrow` 640 / `--content-max` 720 / `--content-wide` 1120, each stepping up at 1600px and 2200px. Prose stays narrow and readable while a studio or table grows, so inner cards keep their proportions instead of stretching. Applied across all 17 surfaces — **seven studios had no cap at all** (Data, Market, Finance, Legal, Channels, Knowledge, Usage).
- **The chat column is one measure.** Header, message list, launcher and composer were full-bleed with only the composer capped, so they never lined up; all four now share `--content-max`.
- **The rail header has 12px of clearance** from the window edge.

## 8. Contrast and motion gates (2026-09-23, after the cut)

Ported from the superseded dark-desk pass (`keep/dark-desk-2026-09-22`, `bac9d3f`) onto the warm desk; the palette itself was not ported.

- `apps/web/lib/motion-tokens.test.ts` (12 tests): a `--motion-1..4` scale (120/180/240/320 ms) with `--ease-out` / `--ease-entrance` (`globals.css:126-146`); the existing `--motion-hover/select/focus/fade` aliases now derive from it (same 120 ms, curve `ease` → `--ease-out`). ## Findings from the 0.15.0 verify pass (2026-09-23)

Product bugs found by the `/maintain-verification-skill` pass on `.cursor/skills/verify-agentforge/`, driven on webdev `:3000` (this checkout, `runtime: "ai"`, a real key) with scratch Playwright. Not fixed here — this pass edits only the skill. Evidence under `.cursor/skills/verify-agentforge/evidence/<feature>/2026-09-23-0.15.0-*` (gitignored). Nothing below was checked on a packed build.

1. **High — creating a desk on a live install strands the whole app on onboarding.** `handlePostWorkspaces` selects the new desk (`packages/host/src/handlers/workspaces.ts:80`), a new desk has no gateway key (keys are per desk), the gate derives `needs_key` / `allowed: false` (`packages/host/src/gateway-gate.ts:295`), and `App.tsx` swaps the whole router for `<OnboardingScreen>` (`apps/web/src/App.tsx:170`, `:250`). Every route, `/workspaces` and `/settings` included, then shows only the key field: no rail, no desk switcher, no way back to Default without pasting a key into the new desk. The selected desk is process-global, so any other open window is stranded too. On the Personal app (no `AGENTFORGE_RUNTIME` set) this is the normal path for anyone who creates a second desk. Driven: create a Legal desk from `/workspaces` → `/chat`, `/workspaces`, `/settings` all render `onboarding-form` only (evidence `workspaces/…-keyless-desk`). Recovered with `POST /api/v1/workspaces/<Default>/select`. Fix direction: carry the key (or the gate) across desks, or keep a desk switcher on the onboarding screen.
2. **Medium — Legal refuses the first upload with raw validator text.** The first file drop creates the matter (`ensureMatter`, `apps/web/components/legal-studio.tsx:91-98`), and the host refuses an empty party or counterparty (`sideSchema`, `packages/host/src/legal/input.ts:26`). The studio shows `side.party is required`, then `side.counterparty is required`, in `legal-error` — English, developer-facing, with no inline hint on the fields. The Run gate checks only the party (`canRun`, `apps/web/lib/legal-view.ts:101-102`), so the UI and the host disagree about what is required. A `.txt` dropped before a matter exists also fires `POST /api/v1/legal/matters` before the client-side `.docx` check can refuse it. With both sides filled the upload and the refusal behave as documented.
3. **Low — the model picker ignores Escape when opened with the mouse.** `openPalette` focuses the search box in a microtask (`apps/web/components/model-picker.tsx:143`), but the panel only mounts once `pos` is set in an effect (`:210`, `:322`), so the ref is null and focus stays on the trigger. Escape is handled only on the search input (`:249`), so it does nothing, and typed characters do not reach the search. Driven: `document.activeElement` = `model-picker`, Escape → panel still open; an outside click closes it.
4. **Low (webdev only) — the 0.15.0 "no key" copy contradicts a saved key when the env pins `stub`.** 0.15.0 maps the gate's `stub` status to needs-key copy (`apps/web/components/chat-key-status.tsx:52-58`; `settings.gateway.status.stub` = `No key saved`, `apps/web/locales/en/settings.json:30`). `deriveGatewayGate` reports `stub` whenever `AGENTFORGE_RUNTIME=stub` is in effect, key or not (`packages/host/src/gateway-gate.ts:292-295`). With `apps/web/.env.local` pinning `stub` and a key saved, Chat said `Connect a key to go live` and Settings said `No key saved` above `Status: Live · Gateway key saved`, while a send went live. The packaged app does not set the env, so this does not reach a Personal user; it misleads every webdev drive.
5. **Low — Chat's "What is this?" promises a sign-in the Personal app does not have.** `chat.empty.whatsThisBody` ends "You can also sign in with a one-time code." (`apps/web/locales/en/chat.json:20`, `id` same line), shown on every build, including desks where `capabilities.sessions` is false (`GET /api/v1/ping` on `:3000`: `sessions: false`) and the sign-in screen is unreachable (§7.4).
6. **Low — dead catalog key left by the "Offline demo" removal.** `chat.empty.statusDemo` ("Model key connected (offline demo)" / "Kunci model terhubung (demo luring)") is still in both catalogs (`apps/web/locales/en/chat.json:17`, `apps/web/locales/id/chat.json:17`) with no reader in `apps/web`.
7. **Low — Meeting delete has no confirmation.** `meeting-delete-<id>` calls `onDelete` on the first click (`apps/web/components/meeting-studio.tsx:381-385`) and removes the meeting folder, recording included. Chat asks with `window.confirm`; Workspaces asks for the typed name.

Also observed, cause not established: the `:3000` process (pid 12032) stopped answering at about 16:27 local, shortly after two locale applies from this pass, and a new process (pid 18740) was listening at 16:28:36. The new process reported `gateway.status: "ok"`, so it was not started with the same env as the old one. Nothing in the host's apply-locale path exits the process (`packages/host/src/handlers/settings.ts`; `apps/web/server.ts:141-144` exits only when `main()` throws). Treat it as unexplained, not as a locale bug.
