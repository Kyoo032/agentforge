## Code: Phase 1, the Phase 2 backend, and the security pass

One switch, `AGENTFORGE_SERVER=1` (`packages/core/src/server-mode.ts`), turns on every hosted-only rule. Webdev and the desktop never set it, and every suite proves they behave as before.

- **Requests:** trusted Origin and Host allowlist (https-only), missing Origin rejected, CSRF double-submit token (`__Host-agentforge_csrf`), path normalisation, `BIND_HOST`.
- **Transport:** `X-Forwarded-Proto: https` required, method allowlist, path filter, header and body caps, content-type allowlist, three rate limiters keyed on the proxy's own forwarded-for hop, 5xx bodies masked, `X-Powered-By` off. Runs on every path, not only `/api`.
- **Secrets and gate:** `AGENTFORGE_SECRETS_KEY` mandatory with a canonical-encoding check, gate fails closed on the hosted build (meta marker injected by `server.ts`), stub runtime closed on the server, both reset scopes refused.
- **Jobs:** ffmpeg and SQL worker limiters in server mode with a queue timeout and abort; a rolling SQL time budget against CTE bombs.
- **Logging:** one JSON logger with secret redaction and dropped prompt and credential fields; 68 console calls replaced.
- **Sessions:** `packages/host/src/auth/` (mint, verify, slide, revoke, purge), table `auth_sessions` (migration 0014), four routes, `session_required` 401 on every API path except auth, ping and components, verified session attached to the request for Phase 3.
- **SQL injection:** 23 sites audited; FTS5 queries now phrase-quoted, one LIKE escaped, SQL worker env stripped of the data dir and secrets, guard scans double-quoted identifiers.
- **XSS:** 23 sinks audited; no raw-HTML sink exists and a guard test keeps it that way; links normalised; artifact files served with a mime allowlist, attachment, nosniff and a sandbox CSP; session cookie `__Host-` prefixed on the server.

Verification at the end of the day: core 2080, db 65, host 1697, web 877 tests passing; lint 0 errors; no new type errors. A throwaway server-mode host on :3100 was driven after each round (origin, CSRF, session, plaintext, TRACE, traversal, content type, oversize body, auth and root floods, forged forwarded-for) and webdev on :3000 answered identically before and after.

## Known gaps, stated plainly

- **Single-tenant until Phase 3.** The session rides on the request, but the tenant still comes from the workspace cookie. No outside user before Phase 3.
- **No sign-in screen.** The four auth routes exist; nothing in the renderer calls them.
- **The portal browser-login contract is assumed** (`grant_type=authorization_code`); the portal doc only specifies device code.
- **Live IDOR, fix first:** `packages/host/src/handlers/edit.ts:494-513` discards an unplaced edit item by raw id with no tenant check. Lane A of the Phase 3 spec, no dependencies.
- CSRF is not bound to the session (Phase 3). Per-tenant caps are Phase 5. PDF, anydoc and DOCX extraction have no concurrency cap, and DOCX extraction blocks the request thread.
- Nothing cleans up disk: edit scratch, datasets, media and renders accumulate.
- Renderer copy (en and id) is missing for `rate_limited`, `https_required` and `reset_disabled`; Settings still offers the reset buttons on the hosted build.
