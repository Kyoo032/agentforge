## Phase E — Market Watch (prompt-driven analyst, any tickers, chart per ticker) — 2026-09-09

**What:** A new job mode, Market. The user pastes a watchlist (up to 15 tickers from any market: `MU, NVDA, SPCX, BBCA, ^VIX …`), keeps or edits a briefing instruction (default: the pre-market favorites briefing in Bahasa Indonesia with TL;DR + confidence, macro, watchlist snapshot, bullish-to-bearish ranking, catalysts, position focus, signals at the open, risk note, under 6,000 characters), optionally pastes position context ("MU: $100 @ $860, $200 @ $900, target $1,000"), and generates. The host resolves symbols, fetches quotes with pre/post-market moves, two years of daily bars, TradingView technical ratings, headlines, and macro levels (S&P/Nasdaq/Dow/Russell futures, VIX, 10Y, WTI, DXY, IHSG, USD/IDR), builds a line chart per ticker (close, SMA50, SMA200), computes the U.S. session from the run clock so a late run never poses as pre-market, and hands the packet plus the instruction to the model, which may call `market_news`, `market_quotes`, `market_history`, `calculator`, and `web_search`/`web_fetch` when a search key exists. Every figure in the prose is checked against the packet, headline figures, and the user's position context; imperative directives are removed; the disclaimer is stamped by code. On demand only; no schedule yet. No server, no sidecar, no port, no Settings fields. First version (LQ45-only, rule-based bull/bear) was rejected by Kyo the same day and replaced; decision record in `market-mode-plan.md`. Built on branch `feat/market-mode` in the `agentforge-market` worktree from `main` 4f1ce13; not merged.

## Phase E2 — Market Watch made usable by a trader, not an operator — 2026-09-10

**Why:** Kyo's verdict on Phase E was that it had no built-in chart you could just look at, and that setting it up was too technical for the person it is for. A trader should not have to read an 18-line Indonesian prompt template before seeing a price. No version bump; this replaces the Phase E studio in place.

**What:** Market now answers before it asks. Type a ticker and a card appears with the live price, the session move, a readable technical line, and a chart — with no API key, no button, and no model call. The written briefing became one clearly labelled step on top of that, and every knob that only an operator cares about moved behind an "Options" toggle.

**Keyless board.** New `POST /api/v1/market/board` (`packages/host/src/market-board.ts`, `handlers/market.ts`, router). It reuses the packet loaders but fetches quotes, bars, and technicals only: `BuildPacketOptions.include` (`market/packet.ts`) now gates headlines and macro, which the board skips, so it is one Yahoo batch plus one TradingView scan. It never calls `requireLive`, so it works on the stub runtime. 400 for a malformed or empty watchlist, 400 `invalid_ticker` when nothing resolves, 502 `market_unavailable` when the sources are down.

**Charts.** `chart-builder.ts` gained named ranges (`CHART_RANGES` 1M/3M/6M/1Y/2Y, default 6M, `buildRangeChart`), and `market-price-chart.tsx` puts the range buttons above every plot — in the board and in the briefing's ticker cards. `buildLineLayout` (`chart-scale.ts`) and `SvgChart` take `zeroBaseline`; price charts pass false, so the axis follows the data instead of anchoring at zero. The plot still spans every series, so at a short range the close line shares the frame with an SMA200 far below it; that is the cost of drawing the average, not a scaling bug. A line with more than 40 points drops its per-point markers, which is what made a 120-bar chart read as a caterpillar.

**Plain language.** `friendlyMarketError` / `needsKey` (`market-client.ts`) turn `runtime_stub` into "Quotes and charts work without a key. To write the briefing, add your API key in Settings." and always render the Settings link (the old copy mentioned Settings and then suppressed the link). `humanRating` prints TradingView's `STRONG_BUY` as "Strong buy". The board says "Above 200-day average" rather than "vs SMA200". The watchlist label is "Which stocks do you follow?".

**Refusing a typo.** `TICKER_PATTERN` / `isValidTicker` / `partitionTickerInput` (`core/src/market/symbols.ts`) accept `^VIX`, `BBCA.JK`, `ES=F`, `DX-Y.NYB`, `BRK-B` and refuse `hello!!` or a 25-character token. `normalizeTickerInput` now filters through it, and the chip input reports what it dropped (`market-ticker-notice`) instead of making a chip that would 400 later. Chip remove buttons went from a 6.6px glyph to a 20px target.

**Contract fix.** `generateMarketBriefing` validated the runtime before the body, so a malformed request answered 503 instead of 400 — the opposite of `/market/regenerate`, which documents the correct order. Swapped, with the test inverted to match and a router case covering both.

**Tests:** core 185, host 143, web 46, all passing. New: `market-board.test.ts`, `use-market-board.test.ts`, ticker-validation and chart-range suites, plain-language error suites. Typecheck and lint unchanged from baseline. Still owed: the packaged desktop drive, and `market.md` re-verified against the new layout.

### Phase E2 follow-up — what two driven test passes found — 2026-09-10

Two agents drove the rewritten studio, one keyless on an isolated stub instance and one live against the gateway. The board itself passed: `mu` + Enter painted a priced card with a three-series chart **825 ms** after the keypress, on the stub runtime, from a single `POST /market/board`; the 11-ticker starter settled all 11 cards in 7.4 s. Three live briefings ran in 38–43 s each, fetch accounting for about 1 s of that, with zero directive sentences and correct use of the position context. DOCX carries the disclaimer at paragraph 1 and last. Fixed here:

- **The error was rendered where nobody could see it.** `market-error` sat at the top of the studio while `market-generate` sat at the bottom of the form; with a watchlist the button is below the fold, so clicking "Write a briefing" with no key changed nothing on screen. The action panel now sits **above** the board, with the error inside it directly over the button, and the board moved below. With 11 tickers the button was at y≈3316; it is now near the top whatever the watchlist length.
- **A finished job's error never cleared** — it survived adding tickers, removing them, and returning to the empty state, because `job.error` is owned by the stream hook and only `applyStarter` reset the local one. Every watchlist edit now goes through one `changeTickers` that marks the error stale.
- **2Y silently dropped SMA50 and SMA200 for every ticker.** The window asks for 504 bars but the host fetched 24 months (~500), so `completeWindow` hit the leading nulls of `smaSeries` and returned null for both. `HISTORY_MONTHS_DEFAULT`/`_MAX` are now 36 (~756 bars, inside the 800 cap), which covers 504 + 199. The old test only asserted the x-axis length, so a new case asserts all three series at every range.
- **The headline price contradicted the line under it.** Pre-market, the card showed the previous close and yesterday's move as a large green number directly above "Pre-market … (-3.05%)" in grey. `headlineOf` (extracted to `lib/market-headline.ts` so it is testable without a DOM) now leads with the latest print and demotes the close to a labelled second line. `^VIX` and `IDR=X` also stopped being priced "in USD".
- **"buy 100 shares" became three chips.** `isValidTicker` now refuses a bare digit run while keeping suffixed numeric tickers (`0700.HK`, `7203.T`). Prose like `apple` still resolves to a chip and then a "could not be found" note; a genuine name-to-symbol lookup is the real fix and is not attempted here.
- **The 15-ticker cap dropped entries silently.** `mergeTickersReporting` computed an `overflow` flag the input never read; it now says so.
- **Touch targets and dark mode.** Chip remove buttons went 20→24 px and range buttons to a 24 px minimum, meeting WCAG 2.2 AA. The change percentage and the error text got dark-mode variants (they measured 2.58:1 and 2.18:1 on the dark surface), as did the amber note block, which was light-on-light.
- **The language select rendered 1084 px wide**, because unlayered `.input { width: 100% }` in `globals.css` beats the `w-auto` utility.

Known and not fixed here, needing a decision or a wider change:

- **The outbound PII masker destroys market data.** `maskOutboundRunInput` runs on every prompt, and `PHONE_RE` swallows an unformatted market capitalisation, taking the source attribution after it with it. The model narrated the damage to the user twice ("market cap: not available (packet field masked)"). Affects every ticker on every run.
- **The number guard reports false positives on every run.** `S&P 500`, `24/7 Wall St.` and `50-day` are flagged as unverified figures because `packetNumbers` harvests numeric fields only, never label text. Three runs, eleven flags, zero real hallucinations. A warning that is always wrong is worse than none.
- **`market-download` is on two buttons** — the studio's DOCX button and the shared artifact bar's Markdown button — so any strict-mode browser test fails on it. Predates Phase E2.
- **The app shell has no responsive breakpoint.** At 390 px the rail keeps 253 px and the studio gets 128 px. `/chat` is equally broken, so this is shell work, not Market work.
- **Dark-mode error contrast is app-wide.** `text-red-700` is used unqualified by chat, data, finance, edit, and artifacts too.
