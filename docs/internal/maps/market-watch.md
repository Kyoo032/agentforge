# Map — Market watch

Last verified: 2026-09-20 at c204e5e

> The rail block was extracted into a shared `rail-submenu.tsx` by a parallel Finance change; `rail-market-specialists.tsx` is now the 82-line adapter that names it.

## Overview

Market is the one job mode that gives something back before any API key exists. Typing a ticker draws a live price and chart; writing a briefing over those numbers needs the gateway. Those are two different routes with two different rules, and the whole page is built so the first one keeps working when the second refuses.

The spine: a named desk picked in the left rail → that desk's own watchlist of chips → `POST /api/v1/market/board` (quotes, bars, TradingView ratings — no key, no model) → `POST /api/v1/market/stream` → one data packet assembled on the user's machine, at the depth and breadth that desk's harness asks for → a shared system prompt plus that desk's own rules → the model drafts JSON, alone at `quick` depth or as an eight-call analyst team at `team` → a number guard and an advice guard rewrite the draft → the briefing artifact → per-section regenerate → DOCX.

What it is not: it is not a trading system and it never tells the reader to act. The advice guard is not advisory — it rewrites the sentence, and the API refuses a briefing that still carries directive language. The board is not a quote feed the model sees; the board deliberately skips headlines and macro (`packages/host/src/market-board.ts:26`).

## How it works

### 1. The rail picks the desk

The agent is chosen in the **rail**, not in the studio. `AppRail` wraps the Market mode row in `rail-market-mode` (`apps/web/components/app-rail.tsx:369`), puts `RailMarketSpecialistsToggle` inside that same `h-8` row (`:349-356`) and renders the desk rows under it while the block is open (`:357`). The collapsed rail returns the bare mode row instead (`:325-327`), with the reason inline (`:319-324`) — the icon column stays pure. Every rail row is `shrink-0` (`:191`), so rows keep their rhythm and the nav scrolls rather than squashing to fit this block in.

**The mechanism is shared, the identity is not.** `rail-market-specialists.tsx` is now a thin adapter (82 lines): it owns the ids and the testid names, and delegates every behaviour to `apps/web/components/rail-submenu.tsx`, which Finance's task list uses too (`app-rail.tsx:328-343`). So `RailMarketSpecialists` (`rail-market-specialists.tsx:60-82`) builds one `RailSubmenuRow` per specialist (`:64-69`) and hands `RailSubmenu` the four testids it must emit — `rail-market-specialists`, `rail-market-specialists-branch`, `rail-market-specialist-<id>` (`:77-79`) — while `useRailMarketSpecialists` (`:29-31`) is one line delegating to `useRailSubmenu(MARKET_PATH)` and `RailMarketSpecialistsToggle` (`:34-52`) just names `rail-market-specialists-toggle` (`:49`). `specialistHref(id)` = `/market?specialist=<id>` stays here (`:24-27`), as does `specialistFromParam` (`:19-22`). **Look in `rail-submenu.tsx` for how it behaves and in `rail-market-specialists.tsx` for what it is called.**

In the shared component: `RailSubmenu` renders the indented branch wrapper (`rail-submenu.tsx:216`) — a hairline down the left under the mode icon so the rows read as a branch rather than a second menu (`BRANCH`, `:34`) — around one scroll container, `role="group"` (`:217-229`), holding one `Link` per row (`:230-244`) that carries `aria-current="true"` only when the pathname is the mode's own route **and** `currentId` matches (`:231`, `:238`). The branch is mounted only while the list is open, so both testids disappear together.

- **Open is derived from the route, not remembered.** `useRailSubmenu` (`:80-103`) returns `open: onMode && !closedOnMode` and `enabled: onMode`; the chevron's close is local state an effect drops the moment the user leaves the route. The owner rule of 2026-09-17 is that the list is open exactly while the user is on that mode — selecting any other rail item minimises it, coming back opens it again — and deriving it is also what keeps the first paint already expanded, with no stored value to read in an effect and so no closed frame (`:68-79`). **Nothing is persisted:** there is no localStorage key at all. Off the route the chevron renders `disabled` (`:123`) and reports `aria-expanded="false"` (`:124`).
- **Height-adaptive, and honest about it.** `listMaxHeight(rows)` is `clamp(MIN_ROWS * ROW_PX, calc(100vh - RAIL_RESERVED_PX), rows * ROW_PX)` (`:64-66`; `ROW_PX = 28` at `:44`, `MIN_ROWS = 4` at `:47`, `RAIL_RESERVED_PX = 700` at `:61`). The comment above the constant is explicit that the rail does not fit on a laptop whatever this block does, so the subtraction buys a shape, not a fit: four rows at 720 and 768, about seven at 900, all eleven from 1008 up. An effect measures `scrollHeight > clientHeight + 1` on mount and on every resize (`:199-213`, measure at `:204`), writes `data-overflowing` (`:228`) and adds a top/bottom fade mask only while rows are actually cut off (`SCROLL_MASK`, `:40`; applied `:223`). The container also carries `mr-1` so its scrollbar does not land in the same lane as the nav's (`:219-223`). The open row is scrolled into view with `block: "nearest"` on mount and on every id change (`:187-192`).

`MarketStudio` reads the id back off the URL rather than offering a picker (`market-studio.tsx:82-88`), and the studio's own header is read-only: `market-specialist-current`, `market-specialist-hint` and `market-specialist-sources` (`:270`, `:274`, `:277`), one node mounted either above the starters (empty watchlist, `:363`) or beside `market-language` (once a chip exists, `:441`), never both. **There is no `market-specialist` select any more**; `apps/web/lib/market-specialist-wiring.test.ts` asserts the testid is gone.

### 2. Chips → the watchlist, one per desk

`MarketWatchlistInput` is a chip box around one `<input>` (`apps/web/components/market-watchlist-input.tsx:145-176`, `role="combobox"` at `:167`, testid `market-tickers` at `:175`, the box itself `market-watchlist-input` at `:121`). Each accepted symbol becomes a `market-ticker-chip` (`:127`). A rejected token produces `market-ticker-notice` (`:212`) from `rejectionMessage` (`:17-20`); typing a partial name opens `market-ticker-suggest` (`:183`) with `market-ticker-option` rows (`:197`) fed by `packages/core/src/market/watchlist-suggest.ts` over `universe.json`.

The cap is `WATCHLIST_MAX = 15` (`packages/core/src/market/watch-schemas.ts:30`), enforced in the schema (`tickerListSchema`, `:326`) **and** in the UI by disabling the input once the fifteenth chip lands (`full` at `market-watchlist-input.tsx:32`, applied `:174`) — the placeholder becomes "That is the maximum" (`:164`) and no notice is shown.

**Each desk keeps its own board.** `apps/web/lib/market-watchlists.ts` stores the chips under `agentforge-market-watchlist:<workspaceId>:<specialist>` (`watchlistKey`, `:38-41`; prefix `:26`; a null workspace is the literal `home`, `:29`), so the crypto desk's coins never drag onto the gold desk (`:1-15`). `loadWatchlist` (`:120-127`) returns what that desk saved, or `specialistStarterTickers(specialist)` when it has never been opened; `saveWatchlist` (`:130-141`) dedupes, trims and truncates to `WATCHLIST_MAX` on every chip change. Storage is best effort: every read and write is wrapped and falls back to a process-lifetime `Map` (`:35`, `:54-86`), so private mode and vitest both work.

The studio wires that up on `scopeKey = ${workspaceId}|${specialist}` (`market-studio.tsx:104`): when the rail moves the URL to another desk it swaps in that desk's watchlist, stales the old error, and — only while the instruction box still holds one of our defaults — swaps in that desk's default instruction (`:136-151`, `nextPrompt` at `:147`). The same effect clamps the depth control back to quick on a desk with no analysts (`:149`). `changeTickers` saves on every edit (`:153-159`). The board refetches off `tickers`, so nothing else has to be told about the move.

Starters: `market-specialist-starter` fills the box with the current desk's own starter list (`:368-379`), beside the three fixed `market-starter` presets (`:380-395`).

### 3. The keyless board

`useMarketBoard` (`apps/web/lib/use-market-board.ts:32-66`) keys its effect on `reloadKey`, the refresh tick plus the joined ticker list (`:35`), and waits `BOARD_DEBOUNCE_MS = 400` (`:7`) before firing (`:59`), so pasting a list is one request. Every fetch carries an `AbortController` that is aborted on cleanup (`:43`, `:61-63`), so a superseded response is dropped. There is **no polling**: the board refetches only when the ticker list changes or `refresh()` bumps `tick` (`:66`), which is what `market-board-refresh` (`apps/web/components/market-board.tsx:146`) calls.

`fetchMarketBoard` POSTs `{ tickers }` to `/api/v1/market/board` (`apps/web/lib/market-client.ts:207-215`). The route is `compile("POST", "/api/v1/market/board", handlePostMarketBoard)` (`packages/host/src/router.ts:268`).

`handlePostMarketBoard` (`packages/host/src/handlers/market.ts:17-23`) is three lines and — uniquely among the Market handlers — **does not call `requireGatewayAllowed`**. Its doc comment says so out loud: "Needs no gateway key." (`:16`).

`buildMarketBoard` (`packages/host/src/market-board.ts:52-67`) parses with `marketBoardRequestSchema` (`packages/core/src/market/watch-schemas.ts:351`), opens the SQLite handle, and calls the same `buildMarketWatchPacket` the briefing uses — with `include: BOARD_SECTIONS` where `BOARD_SECTIONS = { news: false, macro: false }` (`market-board.ts:26`) and **no `specialist`** (`:60-64`). It then runs `requireTickers` (shared with the generate path, `packages/host/src/market-generate.ts:228-237`) and returns `{ tickers, clock, failures }` (`market-board.ts:66`).

So the board and the briefing share one loader. The board is the briefing's packet with two sections switched off, no desk named, and the model never called.

### 4. The specialist harness

Eleven agents, one pipeline. The order is `MARKET_SPECIALISTS` (`packages/core/src/market/specialist-ids.ts:9-21`): `saham`, `forex`, `gold`, `crypto`, `commodities`, `indices`, `sector-rotation`, `scanner`, `summary`, `elliott-wave`, `news`; the default is `saham` (`:24`). The file's own header states the rule: adding an agent is an entry here plus one in the meta, the prompts and the rules — "never a second pipeline" (`:1-7`).

`MARKET_SPECIALIST_META` (`packages/core/src/market/specialists.ts:57-226`, frozen at `:227`) carries, per agent and per language, the label, the hint, the default instruction, the starter tickers and a `focus` tag. `defaultWatchPrompt(specialist, language)` (`:230-233`) is the prefill.

What each desk **reaches for** is `MARKET_HARNESS` (`packages/core/src/market/harness.ts:88-209`, frozen at `:212`), read through `harnessFor` (`:217-219`), which falls back to the first desk rather than throwing. `sources` decides which fetchers run, `historyMonths` sizes the bar request, `headlineCap` trims the news, `tools` / `webResearch` bind the model's tools, `packetOrder` decides which sections `briefing-prompt.ts` renders and in what order (`:1-11`), and `analysts` names the desk's team at `team` depth (`:78-85`). Depth is not a taste: `computeTechnical` needs ~200 daily bars for `sma200` and 252 for the 52-week range, so any desk listing `technicals` — or `signals` / `rotation`, computed from them — asks for 12 months (`:13-18`).

### 5. The packet — resolving, quotes, technicals, charts, news, macro

`buildMarketWatchPacket` (`packages/host/src/market/packet.ts:987-1022`) builds a `PacketContext` (`packetContext`, `:204-225`), resolves the watchlist (`:1000`), loads the sections (`:1001`), assembles one `TickerPacket` per symbol (`:1002`), parses it (`:1004`), then layers the computed sections on and parses again (`:1012`). The progress callback walks `PACKET_PHASES = ["resolving","quotes","technicals","charts","news","macro"]` (`:97`).

- **The harness gates everything.** `hasSource` (`:190-192`) answers off `ctx.harness.sources`, or off `LEGACY_SOURCES` (`:111-118`) when the caller named no desk — exactly the pre-harness set, so the board and the market tools are byte-for-byte what they were (`:105-110`). `historyMonthsFor` (`:195-197`) and `headlineCapFor` (`:200-202`) do the same for depth and headline count; a desk that lists headlines but caps them at zero gets none (`:216-219`).
- **Yahoo Finance** (`packages/host/src/market/yahoo.ts`) is imported as the `yahoo-finance2` package (`:12`) and four of its calls are used: `quote()` (`:95`), `chart()` (`:96-101`), `search()` (`:102`), and — for the analyst team's fundamentals — `quoteSummary()` (`:103-104`). Headlines come out of `search()`'s `.news` array (`parseNews`, `:323`) — there is no separate news API.
- **The fetch ceiling is 36 months.** `HISTORY_MONTHS_DEFAULT = HISTORY_MONTHS_MAX = 36` (`yahoo.ts:41-42`), and the comment above it (`:35-40`) is the reason: the 2Y window is 504 bars and SMA200 needs 199 bars of lead-in, so a 24-month fetch leaves the 2Y chart without its moving averages. 36 months is ~756 bars, inside `HISTORY_BARS_MAX = 800` (`packages/core/src/market/watch-schemas.ts:32`), and the fetcher clamps to it (`yahoo.ts:289`). A desk's harness asks for less (`packet.ts:846`, used at `:848-849`); a caller that names no desk still gets the 36-month default (`packet.ts:195-196`).
- **TradingView** (`packages/host/src/market/tradingview.ts`) POSTs to `https://scanner.tradingview.com/{market}/scan` (`scanUrl`, `:86-88`; origin at `:29`) with `{symbols:{tickers,query:{types:[]}},columns:[…]}` (`scanBody`, `:90-95`). The column order is the contract — the response `d` vector is read by index (comment at `:32`, `TRADINGVIEW_COLUMNS` at `:33`), giving the summary rating and its label plus RSI, close, change, volume, EMA200, SMA50, SMA200, MACD, and the 52-week range (`rowToIndicators`, `:106-131`). Symbols are grouped per screener by `tradingViewMarket` (`groupByMarket`, `:181-193`); an exchange with no mapping becomes a failure string, never a throw (`:187`).
- **CoinGecko + Binance** (`packages/host/src/market/coingecko.ts`) serve the `crypto` section: global market cap and dominance, per-coin cap / 24h volume / 7d change, and the perpetual funding rate. Same posture as TradingView — bare `fetch` to one fixed HTTPS host, a hard timeout, `fetchImpl` injectable (`:1-18`, origins `:22-23`, `CRYPTO_TIMEOUT_MS` `:25`, body cap `:27`). Injection safety is structural: every kept field is a zod-validated number and the only string is the literal `source` the module writes itself (`:10-14`). `loadCrypto` is at `packet.ts:561`, gated by `hasSource(ctx, "crypto")` (`:855`).
- **Metals** (`packages/host/src/market/metals.ts`) is the `gold` desk's section and touches no network: every figure is arithmetic over quotes the packet already fetched (`:1-19`). It publishes a GLD-proxy premium under its own name, `goldFuturesVsGldPct`, and never passes it off as a spot basis (`:9-18`).
- **Concurrency** is `mapLimit(symbols, ctx.concurrency, …)` for histories (`packet.ts:848-849`), news (`:851-852`), fundamentals (`:857-858`) and sentiment (`:860-861`), default 4 (`packages/host/src/market/map-limit.ts:6`, wired at `packet.ts:215`). The TradingView scan is one request per market group, outside that limiter (`packet.ts:386-394`).
- **Cache** is `market_cache` (one row per ticker + kind) plus a `market_news_fts` FTS5 index, in `packages/host/src/market/repo.ts` (`:2-3`, kinds at `:44-58`, write at `:277-300`, news index rebuilt at `:254-265`, retention purge at `:267-274`). TTLs come from core for the four v1 kinds — quote 300 s, technical 900 s, history 6 h, macro 300 s (`packages/core/src/market/staleness.ts:11-21`) — and from the host for everything else (`CACHE_TTL_SECONDS`, `repo.ts:92-106`), starting with `NEWS_TTL_SECONDS = 30 * 60` (`repo.ts:66`) because core's `news` entry is a 90-day retention window, not a refresh interval.
- **Staleness** is one rule: `computeStaleness` marks a row stale when its age is *strictly greater* than the TTL (`staleness.ts:46-49`); exactly at the limit is still fresh. `isInsufficient` (`:52-55`) flags anything past `2 ×` TTL.
- **Swings are per desk now.** `...(hasSource(ctx, "swings") ? { swings: swingPoints(priceHistory?.bars ?? []) } : {})` (`packet.ts:949`). `swingPoints` is a pure pivot-high/pivot-low scan with `SWING_LOOKBACK_DEFAULT = 3` and strict comparison so a plateau yields no pivot (`packages/core/src/market/swings.ts:14`, `:35-51`), capped at `SWING_POINTS_MAX = 12` (`watch-schemas.ts:36`). `elliott-wave` lists it; so does the legacy set, which is why the board and the tools still carry them.
- **The computed sections** run last, over the already-parsed packet, so `computeSignals` / `computeRotation` see the same validated rows the model will (`computedSections`, `packet.ts:973-985`): `metals` (`deriveMetals`, `:975`), `signals` (`:981`; `packages/core/src/market/signals.ts` — RSI bands at 30/70 `:21-22`, a cross within `CROSS_LOOKBACK_BARS = 3` `:24`, 52-week proximity `:26`, an unusual move at `2.5 ×` the 20-bar average `:28-30`), `rotation` (`packet.ts:982`; `packages/core/src/market/rotation.ts` — calendar-day windows 1 / 7 / 30 / 182 `:18-21`, null rather than a short window pretending to be a long one `:8-12`) and `sessions` (`packet.ts:983`; `packages/core/src/market/sessions.ts` — one schedule per venue, `Intl`-driven so DST is the zone database's problem, holidays deliberately not modelled `:1-13`).

**The sources, end to end.** Every fetcher is keyless, host-side, cached in `market_cache` under a named kind and zod-validated; every scrap of free text goes through `sanitizeExternalText` (`packages/host/src/market/sanitize.ts:140-144`, patterns at `:29-47`) and `maskPii`.

### 6. Generate — one streamed job

`market-studio.tsx:177-186` builds the body — `{ prompt, tickers, positionContext, language, specialist, depth, maxChars, model }` — and `job.run("/api/v1/market/stream", body)` (`:187`) drives it through `useJobStream`. `depth` is `requestDepth`, the depth control's value clamped through `nextDepth` (`:119`) so a desk with no analysts can never send `team`.

`handlePostMarketStream` (`packages/host/src/handlers/market.ts:38-49`) gets the tenant, calls `requireGatewayAllowed(loadSettings(tenant.workspaceId))` (`:42`) — "Every path below reaches the gateway, so a closed gate is a 403 here and not a failed call" (`:41`) — then wraps `generateMarketBriefing` in `streamJob` (`:43`).

`generateMarketBriefing` (`packages/host/src/market-generate.ts:502-535`) runs: `parseWatchRequest` (`:510`) → `requireLive` (`:511`) → `loadPacket` (`:522`) → the depth branch, `draftWithTeam` or `draftBriefing` (`:524-527`) → `verifyBriefing` (`:529`) → `saveBriefing` (`:531`), each preceded by an abort check. A malformed body is a 400 whatever the runtime; the gateway check comes once the body is sound (`:509`).

Phases reach the studio as `job.phase` / `job.step` events: the six packet phases with labels from `PHASE_LABELS` (`market-generate.ts:99-106`, emitted at `:318`), then `drafting` (`:342`), `verifying` (`:440`), `saving` (`:465`) — with the four team phases replacing `drafting` on a team run (see step 7). While the model is quiet, `startDraftingHeartbeat` (`:299-307`) emits "Still drafting… Ns" every `DRAFTING_HEARTBEAT_MS = 20_000` (`:97`) so the phase list does not look frozen. The run gets raised watchdog budgets — `MARKET_WATCHDOG_TTFB_MS = 180_000` / `MARKET_WATCHDOG_IDLE_MS = 150_000` (`:90-91`) — which only raise the model floors, never lower them (comment at `:81-89`).

`saveBriefing` (`:461-500`) stamps the artifact metadata with the desk, the depth and — on a team run — the analyst list and the round count (`:473-477`), then auto-ingests the briefing as a Knowledge Base work card (`:486-498`), the same card every other analyst desk writes (`:456-459`).

### 7. The analyst team (depth: `team`)

`quick` is the single-pass briefing that has shipped since v2. `team` splits the same packet between a desk's analysts, runs one bull-versus-bear round, reads the result through three risk lenses, and has an editor write the briefing. **Same pipeline, same guards, same disclaimer — one more depth, not a second product** (`docs/internal/market-team-plan.md:3`).

`MARKET_DEPTHS = ["quick", "team"]` (`packages/core/src/market/team.ts:23`), default `quick` (`:27`), carried on the request as `marketWatchRequestSchema.depth` (`watch-schemas.ts:342`) and on the artifact as `marketBriefingSchema.depth`.

**The call sequence.** `draftWithTeam` (`market-generate.ts:383-430`) binds one `TeamAsk` closure to the tenant, the model and the run's abort signal (`:394-409`) and hands `runTeamPipeline` the packet, the desk, the language, the reader's instruction, `analystsFor(specialist)` and — only for the last call — the desk's harness tools (`:410-420`). `runTeamPipeline` (`packages/host/src/market-team.ts:275-362`) then runs, in this order:

1. **analysts** (`:280-307`) — `mapLimit(wanted, TEAM_ANALYST_CONCURRENCY, …)` with `TEAM_ANALYST_CONCURRENCY = 2` (`:57`), one `job.step` per finished analyst labelled `<done>/<total> <analyst>` (`:285-291`). Each analyst is `runAnalyst` (`:207-228`) with `toolKeys: []` (`:221`) and a prompt that is **only its slice of the packet** — `packetToPromptBlock(packet, specialist, analystPacketOrder(analyst, specialist))` (`:219`) — no reader instruction, no other analyst's view.
2. **debate** (`:309-324`) — the bull sees the analyst notes (`:310-316`); the bear then sees the notes **and the bull's own JSON** (`:317-323`). Sequential by construction; both `toolKeys: []` (`:241`).
3. **risk** (`:326-335`) — one call over notes + bull + bear (`:327-332`), three lenses in one read (`runRisk`, `:248-267`).
4. **synthesis** (`:337-360`) — `teamNotesSchema.parse` first (`:338-344`), then the editor writes `{title, sections[]}` over the full packet block plus all four JSON blobs plus `READER INSTRUCTION` (`:350-357`). This is the only call that keeps the desk's tools (`:359`).

The result is `{ raw, notes, failures, calls }` (`:361`). Back in the host, a `job.step` reports `<calls>/TEAM_MAX_CALLS model calls` (`market-generate.ts:428`), and an empty synthesis is a 502 (`:425-427`).

**Per-desk analysts.** `MARKET_ANALYSTS = ["technical", "fundamentals", "sentiment", "news"]` (`team.ts:33`); which of them a desk runs is `MarketHarnessSpec.analysts` (`harness.ts:85`), read through `analystsFor` (`team.ts:119`) and tested for emptiness by `teamAvailable` (`:124`). Each analyst reads a fixed set of packet sections (`SECTIONS`, `packages/core/src/market/team-prompts.ts:40-45`) **intersected with the desk's own `packetOrder`** (`analystPacketOrder`, `:53-56`) — a section the desk does not fetch stays unseen whatever the analyst is entitled to.

| Desk | Analysts | Model calls | Sections each analyst reads |
|---|---|---|---|
| `saham` | technical, fundamentals, sentiment, news | 8 | technical → quotes, technicals, signals, swings (`team-prompts.ts:41`) |
| `crypto` | technical, sentiment, news | 7 | fundamentals → fundamentals, insiders (`:42`) |
| `news` | news, sentiment | 6 | sentiment → sentiment, headlines (`:43`) |
| `forex`, `gold`, `commodities`, `indices` | technical, news | 6 | news → headlines, globalNews, macro, sessions (`:44`) |
| `summary` | news | 5 | |
| `sector-rotation`, `scanner`, `elliott-wave` | none — quick only | — | |

The three quick-only desks are a decision, not an omission: "a scanner reading a computed table and a wave counter labelling pivots have nothing for four analysts to disagree about, and paying eight model calls to find that out is not a feature" (`harness.ts:78-84`).

**`TEAM_MAX_CALLS`.** `export const TEAM_MAX_CALLS = MARKET_ANALYSTS.length + 4` — **8** (`team.ts:63`). It is enforced in code, not only in a comment: `CallBudget` (`market-team.ts:184-201`) defaults its `max` to it (`:187`) and every stage takes a slot before it calls (`runAnalyst` `:212`, `runSide` `:237`, `runRisk` `:253`, synthesis `:345`). A second, unreachable assert in the host keeps a regression loud (`market-generate.ts:421-424`).

**Phases.** `TEAM_PHASES = ["analysts", "debate", "risk", "synthesis"]` (`market-team.ts:59`), with bilingual labels in `TEAM_PHASE_LABELS` (`:63-68`) resolved by `teamPhaseLabel` (`:70-72`) and emitted at `:280`, `:309`, `:326`, `:337`. The renderer mirrors the same four ids (`MARKET_TEAM_PHASES`, `apps/web/lib/market-client.ts:362`) and relabels them from the web catalog with `localizeMarketProgress` (`:377-395`, key mapper `:368-370`), wired at `market-studio.tsx:127` and rendered into `market-progress` at `:550`. The packet phases above keep the host's English labels; only the team's four are swapped.

**Degrade rules.** No stage but the synthesis may fail the run (`market-team.ts:269-274`):

| What went wrong | What the run does |
|---|---|
| An analyst call fails, times out, or does not parse | `unavailableAnalystNote(analyst)` — `summary: "<unavailable>"`, `keyPoints: []`, `confidence: "low"` (`team.ts:114-116`) — plus `team: <analyst> analyst unavailable (<reason>)` in `failures` (`market-team.ts:225-227`) |
| The budget ran out before a stage | that stage is `… skipped (call budget spent)` (`:213`, `:238`, `:254`) |
| Bull or bear fails | `unavailableSide(stance)`, thesis `<unavailable>` (`:120-122`, `:243-245`) |
| The risk read fails | `unavailableRisk()` — all three lenses say so (`:125-131`, `:265`) |
| The budget is spent before the synthesis | the pipeline **throws** (`:345-347`); this is the one stage that can fail the run |
| The desk has no analysts | falls back to the quick draft plus `team: the <desk> desk has no analyst team; wrote a quick briefing instead` (`market-generate.ts:388-393`), and the saved briefing's `depth` is `"quick"` (`:445`) |

**Guards over the stored notes.** What the team stores on `briefing.team` is guarded exactly as hard as what the reader sees. `guardTeamNotes(notes, allowed)` (`market-team.ts:158-179`) runs `guardText` — the number guard then the advice guard, in that order (`:136-138`) — over every free-text field: each analyst's `summary` (`:162`) and `keyPoints` (`:163`), both debate sides' thesis, points and rebuttals (`guardSide`, `:144-151`, applied `:166-167`), each lens's `view` and `keyRisks` (`:171-172`), and the volatility and liquidity lines (`:174-175`). Enums (`confidence`, `stance`, `lens`, `rounds`) pass through, and the whole thing is re-parsed through `teamNotesSchema` on the way out (`:159`). It is called once, in `verifyBriefing`, over the same `allowedNumbers(packet)` the sections get (`market-generate.ts:446`) — which is why the appendix renderers deliberately do **not** re-guard (`market-briefing-build.ts:312-313`, `market-docx.ts:190-191`).

**Where the notes surface.** Markdown: `teamAppendixMarkdown` (`market-briefing-build.ts:318-364`) under the briefing, spliced in by `marketBriefingMarkdown` (`:371-381`). DOCX: `teamBlock` (`market-docx.ts:193-222`), mounted between the headlines and the sources (`:255`). Renderer: `MarketTeamPanel` (`apps/web/components/market-team-panel.tsx:113`), mounted only when `briefing.team` exists (`market-briefing-view.tsx:188-192`) with `testIdPrefix="market-team"` (`:190`) — so the panel is `market-team` (`market-team-panel.tsx:139`), the disclosure `market-team-toggle` (`:149`), the cards `market-team-analyst-<analyst>` (`:161`, rendered `:71` with `data-confidence`), the columns `market-team-bull` / `-bear` (`:167-168`, rendered `:89` with `data-stance`) and the lenses `market-team-risk-<lens>` (`:175`, rendered `:105` with `data-lens`).

The studio's depth control is `market-depth`, a `role="group"` segmented pair (`market-studio.tsx:290-320`): one `market-depth-<option>` button per depth (`:307`), `market-depth-team` `disabled` on a desk with no analysts (`:306`), and a single muted line that is `market-depth-hint` or `market-depth-unavailable` depending on `teamReady` (`:315`). It is written once and mounted at both of the header block's placements (`:364`, `:440`), so the two can never drift.

### 8. System prompt + rules

`buildWatchSystemPrompt` (`packages/core/src/market/briefing-prompt.ts:100-122`) is the shared contract, called from `draftBriefing` (`packages/host/src/market-generate.ts:350-355`). Every line number in the bullets below is in `briefing-prompt.ts`:

- the desk's own name in the first line, from `MARKET_SPECIALIST_META[specialist].label` (`briefing-prompt.ts:104`, `:106`);
- "Every number in your output must be one of the numbers in the DATA PACKET or … USER POSITION CONTEXT" plus the promise that a guard replaces anything else with the unverified marker (`:111`);
- "Rank the tickers and read sentiment freely … but never tell the reader to buy or sell now. No imperative directives." (`:112`);
- output language and `maxChars` (`:115`), the clock note when there is one (`:102`, `:116`);
- JSON-only output, `{"title", "sections":[{"heading","body"}]}` (`:117`);
- then `specialistSystemRules(specialist, language)` appended as further bullets (`:120`).

`specialist-rules.ts` holds those bullets, one localized set per agent (`:15` onward); the header states the invariant — the house rules stay in `buildWatchSystemPrompt`, no rule line may contain an imperative directive, and `specialists.test.ts` asserts the advice guard over all of them (`specialist-rules.ts:1-10`). At `team` depth the role prompts in `team-role-prompts.ts` carry the same floor and add the refusals: "No rating, no price target, no directive, no position size" (`:140` en, `:147` id).

**The data packet is per desk, and per reader.** `packetToPromptBlock` (`briefing-prompt.ts:178-196`) reads `harnessFor(specialist).packetOrder` (`:184`) and prints only those sections, in that order: whole-packet renderers from `PACKET_SECTIONS` (`:129-137`) and per-ticker lines from `TICKER_SECTIONS` (`:144-153`), with the ticker blocks emitted where the first ticker-level source appears (`:186`, `:191`). A desk whose harness never names a section simply never sees it. The third argument, `only`, **narrows that order and never widens it** (`:173-177`, applied `:183-184`): it is how an analyst is handed its own slice and nothing else. The renderers themselves live in `packet-sections.ts`, which prints figures at presentation precision and spells period labels out ("1 month", not "1m") so the number guard never reads a token as a million (`:1-10`).

The single `specialist === "elliott-wave"` branch that used to sit in this file is gone — swings are a `packetOrder` entry like any other (`briefing-prompt.ts:151`).

### 9. The two guards

`buildMarketBriefing` (`packages/host/src/market-briefing-build.ts:233-257`) runs both over the model's draft:

1. **Number guard.** `allowedNumbers(packet)` (`:161-163`) delegates to `packetNumbers` (`packages/core/src/market/packet-numbers.ts`), which collects every figure the packet sections, the headlines the model actually saw, and the position context contain — with the rule that any new numeric field on a harness section must be listed there or the model is punished for repeating a number code handed it (`:1-13`). `guardNumbersSkippingPeriods` (`market-briefing-build.ts:132-144`) first masks period labels and clock times (`PERIOD_LABEL`, `:124-126`) with a sentinel (`:127-129`) so they are not mistaken for figures, runs core's `guardNumbers`, then restores them. Anything left over becomes the unverified marker and is counted.
2. **Advice guard.** `guardBriefingSection` (`:147-158`) runs `guardAdviceInText` over the body and `ADVICE_PATTERN` over the heading. A directive sentence is replaced, not flagged.

The result is `{ briefing, guard: { flagged, total, adviceReplaced } }` (`:256`), with `guardedSections` counting the sections the advice guard touched (`:253`) and `MARKET_DISCLAIMER` stamped by code (`:254`) — the model never writes it.

Then the belt-and-braces pass: `assertBriefingHasNoAdvice` (`:264-276`) re-runs `assertNoAdvice` and, on a leak, logs and throws `ApiError("advice_leak", …, 502)` (`:272`). It runs on four call sites across three occasions — on save after drafting (`market-generate.ts:466`), on regenerate both over the client-supplied briefing (`:574`) and over the rewritten section (`:603`), and on DOCX export (`handlers/market.ts:73`) — so a briefing that somehow carries directive language cannot be re-exported later.

## Gotchas

- **The desk is in the URL, not in the studio.** `market-specialist` (the old `<select>`) has count 0 — a recipe that reaches for it fails on a page that is working correctly. Pick a desk with `rail-market-specialist-<id>` and read the result off `?specialist=`, `market-specialist-current` and the chips.
- **The rail block does not exist on a collapsed rail.** `app-rail.tsx:325-327` returns the bare mode row, so `rail-market-mode`, `rail-market-specialists-branch`, `rail-market-specialists`, `rail-market-specialists-toggle` and every `rail-market-specialist-<id>` are count 0 there.
- **The block exists only on `/market`, and nothing about it is stored.** `open` is `onMode && !closedOnMode` (`apps/web/components/rail-submenu.tsx:80-103`), so off Market both `rail-market-specialists-branch` and `rail-market-specialists` are count 0 and the chevron is `disabled` with `aria-expanded="false"` — not a bug, the owner rule of 2026-09-17 (`:68-79`). Closing the chevron while on Market works; leaving and coming back opens it again. There is **no** `agentforge-rail-market-specialists` key: `apps/web/lib/rail-market-specialists-wiring.test.ts` asserts `rail-prefs.ts` never grows one. ## Why

**Why the board exists as a separate, keyless route.** `[Direct]` `packages/host/src/handlers/market.ts:16` — "Needs no gateway key." `[Direct]` `packages/host/src/market-board.ts:1-6` — the module comment says it fetches quotes, bars, technicals and a chart "straight from the packet loaders; no headlines, no macro, no model" and that "it works before any API key is saved". `[Supported]` the studio's own refusal copy, "Quotes and charts work without a key. To write the briefing, add your API key in Settings." (`apps/web/lib/market-client.ts:218-219`), is written on the assumption that the board keeps running through a refusal. **Confidence: high.**

**Why the history fetch is capped at 36 months.** `[Direct]` `packages/host/src/market/yahoo.ts:35-40`: "The 2Y chart window is 504 bars and SMA200 needs 199 bars of lead-in before the first plotted point, so a 24-month fetch (~500 bars) leaves the 2Y window without its moving averages. 36 months is ~756 bars, inside HISTORY_BARS_MAX (800)." `[Supported]` driven 2026-09-17: at every range from 1m to 2y the board chart drew three lines, with 22/66/126/252/504 points, matching `CHART_RANGES` (`packages/core/src/market/chart-builder.ts:48-54`). Note that `market-board.ts:1-6` still says "two years" — the comment is stale, the constant is not. **Confidence: high.**

**Why each desk has its own harness rather than one packet for everyone.** `[Direct]` `packages/core/src/market/harness.ts:1-11` — "a scanner has no business paying for headlines and a wave counter needs two years of bars, not six months. This table is the single place that says so." `[Direct]` `:13-18` fixes the depths against the indicators: `computeTechnical` needs ~200 bars for `sma200` and 252 for the 52-week range, and `sector-rotation` needs a base bar six months back for `ret6mPct`. `[Direct]` `packages/core/src/market/briefing-prompt.ts:166-177` — which sections the DATA PACKET carries is the chosen desk's harness speaking, "which is the whole point of the harness". **Confidence: high.**

**Why the computed sections are computed rather than narrated.** `[Direct]` `packages/core/src/market/signals.ts:4-8` — a scanner used to be asked to spot RSI extremes and moving-average breaks by reading a wall of numbers, "which is exactly the job a model is worst at". `[Direct]` `rotation.ts:4-6` — "who led and who lagged" is arithmetic over bars, not narration. `[Direct]` `swings.ts:1-4` — pure and deterministic "so every level the model labels is a level code found". `[Direct]` `packages/host/src/market/metals.ts:1-4` — no network, "so the model never has to eyeball a ratio". **Confidence: high.**

**Why the desk is picked in the rail and not in the studio.** `[Direct]` `apps/web/components/rail-market-specialists.tsx:54-59` records the owner decision of 2026-09-17: the Market agents sit under the Market rail entry "the way the chat sessions sit under Chat", each with its own harness and its own watchlist, so "the studio reads `?specialist=` back off the URL rather than offering a second picker". `[Direct]` `app-rail.tsx:319-327` gives the collapsed-rail carve-out: the icon column stays pure. `[Direct]` `apps/web/components/rail-submenu.tsx:68-79` records the follow-on rule of the same day: the list is open exactly while the user is on Market, and the chevron's close is dropped on leaving, so nothing is persisted. `[Direct]` `:49-61` is the sizing decision and its measurement: the rail does not fit on a laptop whatever this block does, so the reserved height buys a shape (four rows at 720/768, all eleven from 1008) rather than a fit. `[Supported]` `apps/web/lib/market-watchlists.ts:1-9` is the consequence — one board per desk per workspace, which only makes sense if the desk is a place you navigate to rather than a dropdown value. **Confidence: high.**

**Why there is one pipeline and eleven agents rather than eleven pipelines.** `[Direct]` `packages/core/src/market/specialist-ids.ts:1-7`: "One pipeline (packet fetched and computed in code, model narrates, number guard and advice guard unchanged); what differs per agent is the system rules, the default instruction, and the starter watchlist. Adding an agent is an entry here plus one in the meta, the prompts, and the rules — never a second pipeline." `[Direct]` `packages/core/src/market/specialist-rules.ts:1-10` adds the guard-rail: every rule line is a bullet under the shared "Rules:" heading and none may contain an imperative directive, asserted by `specialists.test.ts`. **Confidence: high.**

**Why the analyst team stops where it does — what was refused from TradingAgents.** The team's shape is adapted from [TradingAgents](https://github.com/TauricResearch/TradingAgents) (Apache-2.0); no prompt text is copied and everything in `packages/core/src/market/team*.ts` is written from scratch in both languages (`[Direct]` `docs/internal/market-team-plan.md:5`, echoed at `packages/core/src/market/team-prompt-parts.ts:10`). What was adopted is four analysts on **disjoint slices** — "the value is not four models, it is four *slices*" (`market-team-plan.md:9`) — one bull/bear round, three risk lenses in one call, and no tools for the analysts, because tool-calling analysts drift and re-fetch (`:12`). The refusal table at `:16-23` is the rest of the answer, and each refusal has a mechanism behind it rather than a promise:

- **A trader agent** (`market-team-plan.md:18`) — "its output is a decision", against Market's first principle of analysis, not a directive.
- **A portfolio manager, position sizing, allocation** (`market-team-plan.md:19`) — "it is investment advice with a licence attached to it"; `FORBIDDEN_FIELD_NAMES` already bans `position` and `allocation` on any market schema.
- **An execution or order layer** (`market-team-plan.md:20`) — "the one irreversible thing in this domain".
- **Five-tier BUY…SELL ratings** (`market-team-plan.md:21`) — "a rating *is* an imperative with a label on it", and the advice guard scans phrases, so it would not catch one. The refusal therefore lives in the schema (`riskReadSchema` and `teamNotesSchema` carry no rating field) and in the prompt (`team-role-prompts.ts:140`, `:147`).
- **Price targets** (`market-team-plan.md:22`) — a model-derived target is a number that is not in the packet, so the number guard stamps `[unverified figure]` on it anyway; a target from the reader's own position context stays allowed, as it always has.
- **Reflection or memory across runs** (`market-team-plan.md:23`) — "later, if ever. It is a second store and a second privacy question."
- **A second debate round** (`market-team-plan.md:33`, still open at `:87`) — one round, `TEAM_ROUNDS = 1` (`packages/core/src/market/team.ts:60`), until a run shows the single round ending on an unanswered point often enough to matter.

`[Direct]` the code restates the same list in its own header (`team.ts:8-12`, `team-role-prompts.ts:5-9`). **Confidence: high.**

**Why the advice guard runs on every exit.** `[Supported]` it is called on save after drafting (`packages/host/src/market-generate.ts:466`), on regenerate over the client-supplied briefing (`:574`) and again over the rewritten section (`:603`), and on DOCX export (`packages/host/src/handlers/market.ts:73`), each throwing `502 advice_leak` (`packages/host/src/market-briefing-build.ts:272`). `[Inferred]` the export-time call is the one that cannot be explained by drafting alone: a briefing is a client-supplied body on `/market/docx` (`handlers/market.ts:66-68`), so the only way to keep a directive sentence out of an exported document is to re-check the body on the way out rather than trusting that it was guarded when it was written. Inference chain: the route parses the briefing from the request, not from storage → the request is client-controlled → a guard that only ran at draft time would not cover it. **Confidence: medium for the intent, high for the mechanism.**

**Why the team's stored notes are guarded separately from the sections.** `[Direct]` `docs/internal/market-team-plan.md:25` — the guards "now run twice: over the synthesis output, and over every free-text field of the stored `team` notes … so the stored notes are as clean as the rendered sections." `[Direct]` `packages/host/src/market-team.ts:19-21` says the same in the module header. `[Inferred]` the reason it has to be a separate pass is that the notes never go through `buildMarketBriefing`'s section loop: they arrive as their own JSON objects and are rendered by the appendix writers, which explicitly do not re-guard (`market-briefing-build.ts:312-313`, `market-docx.ts:190-191`). A guard that only covered `draft.sections` would leave the appendix — analyst summaries, both debate theses, three lens views — unguarded in the artifact, the markdown and the DOCX alike. **Confidence: high.**
