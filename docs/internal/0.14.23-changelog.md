## Knowledge ingest loop — 2026-09-08

- **What:** the Knowledge Base grows as you use the desk. Whenever Chat or a job mode successfully produces something, the host writes a **work card** (title, mode, prompt excerpt, pointer, capped body ≤ 8k chars) into `knowledge_sources` / `knowledge_chunks` / `knowledge_vectors`. Files (mp4, png, DOCX, PPTX) stay in `media` / `artifacts`; Knowledge stays text RAG. Chat then retrieves cards, not bytes. Knowledge → Sources shows the cycle (`knowledge-loop`).
- **DB:** `knowledge_sources.origin_kind` / `origin_id` (nullable) + unique index `knowledge_sources_origin_idx (workspace_id, origin_kind, origin_id)`. `packages/db/src/schema.ts`, `drizzle/0008_knowledge_source_origin.sql` (+ journal entry; the SQL is a safe `CREATE TABLE IF NOT EXISTS` because SQLite has no `ALTER TABLE IF EXISTS` and a journal stamped past 0003 may lack the table), and `ensure-schema.ts` `ensureKnowledgeSourceOrigin` which adds the columns + index to existing tables (same healing pattern as `workspaces.template_pack`). Manual sources (File / URL / Paste) keep NULL origins; SQLite treats NULLs as distinct so they never collide.
- **Host:**
  - `knowledge.ts`: `KnowledgeSource.origin`, `findSourceByOrigin`, `indexKnowledgeSource` (replace semantics: reusing an id rewrites row + chunks + vectors in one transaction), `markSourceFailed`, `WORK_SOURCE_TYPES` (`Chat`, `Documents`, `Research`, `Finance`, `Data`, `Images`, `Videos`, `Presentation`, `Edit`), `KNOWLEDGE_SOURCE_TYPES`. `retrieveChunks(..., { excludeSourceIds })` and `knowledgeInjection(tenant, query, { excludeThreadId })` skip the asking thread's own card (FTS and vector paths both filter on `source_id`). `knowledge-embed.ts` `retrieveVectorChunks` takes the exclusion list.
  - `work-cards.ts` (new): `WorkCard`, `renderWorkCard` (self-describing header + capped body, `[truncated]` marker), `mediaWorkCard` / `artifactWorkCard` / `chatWorkCard`, `documentDraftMarkdown`, `presentationOutlineMarkdown`, `titleFromPrompt`, `capText`.
  - `knowledge-ingest.ts` (new): `upsertWorkSource(tenant, card)` — idempotent on origin, never throws, empty card → skipped, index error → `Failed` row with reason; `ingestWorkSource` fire-and-forget variant.
  - Call sites (after successful persist only): `studio-generate.ts` `generateStudioImage` / `generateStudioVideo` (third arg `{ workType }`; `edit/wire-generate.ts` passes `"Edit"`), `research-generate.ts`, `data-generate.ts`, `finance-generate.ts` (after the artifact row exists), `document-generate.ts` and `presentation-generate.ts` (now also persist a `draft` artifact in mode `documents` / `presentations`, then ingest `artifact:<id>`; the returned draft / outline shape is unchanged), `runs.ts` (after `finishRun(completed)` with assistant text: one `Chat` card per thread, title from the thread, latest user + assistant only; fire-and-forget so stream end is not delayed).
  - `handlers/knowledge.ts`: `POST /api/v1/knowledge/sources` accepts `artifactId` — if that artifact's card exists → `200 { ...source, alreadyIndexed: true }`, else index it once as the work type (`Dossier`→`Research`, `Analysis`→`Data`, `Brief`→`Finance`, or by artifact mode) → `201 { ...source, alreadyIndexed: false }`. `GET /api/v1/knowledge/context?threadId=` applies the same skip-self rule for the context popover.
- **Web:** `lib/knowledge-loop.ts` (`countSourcesByType`, `summarizeLoop`, `isWorkSourceType`, `barFraction`, `WORK_SOURCE_ORDER`, `LOOP_STAGES`), `components/knowledge-loop.tsx` (cycle SVG + summary + one bar per type using the validated `chartPalette(0)` hue; single-series, so no legend; text stays in ink tokens), mounted at the top of the Sources tab in `knowledge-page.tsx`. `knowledge-source-type` testid on the row tag; Failed rows show the reason on hover. `lib/artifacts-client.ts` `sendTextToKnowledgeBase` takes `artifactId` and returns `{ alreadyIndexed, status, error }`; `artifact-actions.tsx` shows `Already in the Knowledge Base.` / `Added to the Knowledge Base.` / the Failed reason. `chat-session.tsx` passes `threadId` to the context call.
- **Testids:** `knowledge-loop`, `knowledge-loop-cycle`, `knowledge-loop-summary`, `knowledge-loop-work`, `knowledge-loop-manual`, `knowledge-loop-indexed`, `knowledge-loop-failed`, `knowledge-loop-chunks` (each with `data-value`), `knowledge-loop-counts`, `knowledge-loop-count-<Type>` (`data-count`), `knowledge-loop-empty`, `knowledge-source-type`.
- **Tests:** db `ensure-schema.test.ts` (+2: origin columns + unique index; heal after dropping them) → 14; host `work-cards.test.ts` (7), `knowledge-ingest.test.ts` (4: upsert twice → one source with rewritten chunks; empty skipped; retrieve + injection exclude the asking thread but keep others; three turns → one Chat row holding the latest answer) → host 209; web `knowledge-loop.test.ts` (4) → 152. `vite build` green. No live gateway in unit tests (stub embeddings).
- **Design rules kept:** no bytes copied into `data/media/knowledge/`; one source per origin; Chat never retrieves its own last reply; stub runtime still indexes; index failure never fails the work; example clips never `POST /api/v1/videos` so they never ingest.
- **Verify on webdev, then the installed app:** [`.cursor/skills/verify-agentforge/features/knowledge-ingest.md`](../../.cursor/skills/verify-agentforge/features/knowledge-ingest.md). Short form: send in Chat → `/knowledge` shows a `Chat` row and `knowledge-loop-count-Chat`; second send in the same thread keeps one row; Videos **Use this prompt** adds nothing; live Generate (only if asked) adds `Videos` and the gallery keeps the clip; `research-send-kb` after a dossier reads `Already in the Knowledge Base.`.
- **Out of scope:** indexing pixels / ASR transcripts; backfill of deleted gallery rows; anything inside 0.14.22.

## Hardening round (probe agents: secrets / concurrency / offline) — 2026-09-08

Three probe agents drove an isolated stub instance (`PORT=3100`, own data dir); a second instance on `:3102` re-verifies the fixes. Nothing on `:3000` was touched.

- **CRITICAL fixed — plaintext PII and injection text in work cards.** Chat messages are sealed at rest but `knowledge_chunks` (FTS5) and `knowledge_vectors` are plaintext, and every ingest path indexed the raw text. `upsertWorkSource` now runs `maskPii` over the rendered card and its title, and `scanInjection` over the card (owner `injectionGuardBypass` honoured, same as attachments / source material): a hit records a `Failed` row `injection_blocked (rule: …)` with zero chunks, so an injected sentence can never be served back as `## Retrieved sources` to another thread. A later clean turn in the same thread replaces the blocked row. Tests: `knowledge-ingest.test.ts` (+2).
- **FTS5 query hardening.** `knowledgeFtsQuery` quotes every token as an FTS5 string, so `NEAR(`, `AND`, `col:x`, `-foo`, `x*` are literal words (was: silent `[]` via the catch). Test: `knowledge.test.ts` (+1).
- **Event loop: catalog memo.** `listCatalogModels()` cost ~230 ms of synchronous work (182 models × models.dev registry) and ran on every Chat run and every knowledge lookup, serialising all requests (15 parallel runs finished 1.0 → 13.5 s apart; stub TTFB ~950 ms). Memoized on the two cache files' mtime+size (`modelCacheStamp`, `modelsDevCacheStamp`); any probe or registry refresh rewrites its file and invalidates. Test: `selectable-models.test.ts` (+1).
- **Runs never stuck `streaming`.** The TTFB watchdog and client-abort paths in `runs.ts` now call `finishRun(failed, message)` (observed: 31 rows `streaming` forever under a hung gateway). `http-adapter.ts` wires a client-disconnect `AbortSignal` (was desktop IPC only), so a closed tab stops the live model call.
- **KB cascade on delete.** `deleteThread` and `DELETE /api/v1/artifacts/:id` remove the matching work card (`deleteSourceByOrigin`); before, a deleted conversation kept being retrieved. `deleteSource` is one transaction.
- **Vector consistency under races.** `indexSourceVectors` writes only if the source row still exists with the `created_at` captured at index time (a delete or re-index during a remote embed is a no-op instead of an orphan); `retrieveVectorChunks` joins `knowledge_sources` so an orphan is never served. Test: `knowledge-ingest.test.ts` (+2); `knowledge-embed.test.ts` seeds source rows.
- **Malformed input → 4xx, not 500.** Invalid JSON body → `400 invalid_json`; `POST /threads` with non-string `agentId` / `title` → 400, title capped at 200 (`THREAD_TITLE_MAX`); pasted knowledge `name` capped at 200 (`PASTED_SOURCE_NAME_MAX`); whitespace paste text → 400 (was a permanent `Failed` row).
- **Verified robust by the hammer (old build, still true):** one source per thread under 5 concurrent runs / 15 parallel threads / 30 rapid turns / delete races; chunks = FTS rows = vector rows; zero orphans; aborts before/after first byte leave no hung runs; FTS metacharacters, unicode, NUL, 5 KB queries all 200; 30-way parallel knowledge writes/reads no 5xx.
- **Not changed (noted):** `/api/v1/ping` returns the gateway base URL (not a secret; loopback only). Media rows have no delete endpoint, so no media cascade exists yet.
- Totals after this round: host 216, db 14, web 152 tests green; host `tsc` clean apart from pre-existing `edit/` errors.

## Hardening rounds 2–3 (offline requirement, guard bypasses, run/thread scoping) — 2026-09-08

Requirement restated by the owner: the whole system must run **local, with no internet**. Only a user-saved gateway key makes live model calls optional. An offline audit (refused port and black-holed TCP listener as the two network shapes) and second-round security / concurrency probes drove these changes.

- **Offline: Chat fails fast instead of hanging 120 s per message.** `ai-sdk-runtime.ts`: `maxRetries: 0` on `streamText` (the host's 3-attempt contact loop owns retries) and `result.usage` is no longer awaited after a failed stream (in `ai` 4.3 it never settles after an `error` part); when awaited it is bounded to 5 s. Measured before: 120 s refused / 140 s black-hole, reported as the misleading "No first token".
- **Offline: Settings save is bounded.** `probe.ts`: 5 s timeout per probe request and `detectCompatibleApi` stops after the first network-level failure (`isNetworkUnreachableError`) instead of trying four dialects × undici's 300 s. Measured before: 1233 s on a black-hole. `refreshModelCache` no longer probes when there is no key and the base URL is the gateway default (stub desks called out on every save). The models.dev registry (4.5 MB download, 8 MB rewrite on every save) is refreshed at most weekly unless the user presses Refresh (`POST /api/v1/models` → `forceRegistry`).
- **Offline: embeddings.** `knowledge-embed.ts` timeout 20 s → 4 s plus a 5-minute circuit breaker: after one failure every batch uses local stub vectors immediately. This was on the hot path of every chat message and every KB write (20 s each on a black-hole).
- **Offline: app shell gate.** `account.ts` `FETCH_MS` 8 s → 3 s; `account-usage.ts` remembers a failed pricing fetch for 2 min so `GET /settings` / `GET /usage` pay the timeout once. Measured before: 16 s "Starting Agentforge…" on a black-hole.
- **Offline: renderer.** Barlow / Barlow Condensed woff2 (latin + latin-ext, OFL) bundled under `apps/web/app/fonts/` with `@font-face`; the Google Fonts `@import` and `preconnect`s are gone. `dist/` contains no `googleapis` / `gstatic` reference.
- **Offline: desktop.** `auto-update.cjs` skips the startup check when Electron's `net.isOnline()` is false (manual Check still works). `model-cache.ts` / `models-dev-cache.ts` resolve under `AGENTFORGE_DATA_DIR` when set (packaged app: userData, not `cwd/../../data`).
- **CRITICAL fixed — injection guard bypasses.** `injection-guard.ts`: the text-wide "false positive" shortcuts are removed (appending `notes.txt` + a base64 run, or the words "false positive", used to disable every rule); rules now match on `normalizeForScan(text)` = NFKC + zero-width characters stripped + Cyrillic/Greek homoglyphs folded (a Cyrillic `о` in "Ignоre" bypassed the guard). Tests: `injection-guard.test.ts` (+2, one rewritten). Owners with legitimate material use the existing `injectionGuardBypass`.
- **CRITICAL fixed — threads were not workspace-scoped.** `getThread` / `deleteThread` filtered on organization + user only, so a Workspace-A session could read and delete a Workspace-B thread (and the new KB cascade then orphaned B's card). Both now filter on `workspaceId` too; `GET /knowledge/context?threadId=` only honours a thread the caller's workspace owns.
- **Run finalization race.** `finishRun` only transitions a `streaming` row (returns whether it did); once the watchdog or a client abort has settled a run, a late model answer is dropped instead of being persisted as a completed turn.
- **Same-origin writes.** `replaceSourceRows` folds a row that already owns the origin into the write inside the transaction (the unique index can never throw); `created_at` is strictly increasing per write so the vector staleness guard cannot be defeated by two writes in one millisecond. Artifact delete cascade is wrapped so a KB error can never fail an already-done delete.
- **Concurrent-edit note.** Another session is adding a Legal mode in the same tree (`packages/core` templates, product modes, artifacts, `docx/validate`, `PASTED_SOURCE_TYPES` gained `Memo` / `Playbook`). Two core test files fail from that work (`docx/write.test.ts` missing `./validate`, `templates/library.test.ts` expects `legal`); none of the failures are in the files touched here. The knowledge `KB_TYPE_TO_WORK` map was made a partial record so their new types compile.
- Totals: core 704 / 705 (the 1 failure + 1 unloadable file are the Legal work), host 216, db 14, web 152, desktop updater + lifecycle ok; `vite build` green.

## Hardening round 4 (round-2 hammer on the fixed build) — 2026-09-08

Re-probe of `:3102` (fixed build) confirmed on the live host: stub run TTFB median 58 ms (was ~950), 15 parallel runs ~35 ms apart (was ~900), invalid input → 4xx everywhere, thread delete cascades the card, watchdog finalizes a hung run, PII masked in name / chunks / vectors, injection turn → `Failed` card with zero chunks. Three more fixes from its findings:

- **Client abort before the run row exists.** `runs.ts` keeps the abort message; right after `insertRun` a run that was already settled is finalized `failed` and the work stops (before: it sat `streaming` until the 120 s watchdog).
- **Guard no longer re-trips on the thread title.** The title is derived from the first user message, so a thread opened with an injection sentence could never get an `Indexed` card again. `upsertWorkSource` now decides on body + prompt only and replaces a tripping title with the mode name. Test: `knowledge-ingest.test.ts` (+1).
- **Orphan sweep.** `sweepOrphanThreadSources` (called from `GET /api/v1/knowledge`) drops Chat cards whose thread is gone (workspace-scoped, one transaction). Test (+1).
- Still open from that report: host `console.warn` lines do not reach the webdev `server.log` capture, so "no unhandled rejections" cannot be proven from the log alone.

## Legal mode v1 (.docx matter review) — 2026-09-08

- **What:** a new work mode `legal` (`/legal`, rail `mode-legal`; Home and the Legal preset seed it, Marketing / Students do not). ## Videos: bundled example clips + upstream-refusal error text — 2026-09-08

- **Poll parser.** `gateway-media.ts` read NewAPI's envelope `code: "success"` as the error, so a refused job surfaced as "success" (HTTP 400). Observed: `grok-imagine-video` on this key returns `FAILURE` / "upstream refused" within about 60 s; `veo_3_1-fast` completes and only accepts 4 / 6 / 8 s.
- **Chat: model-contact probing hidden.** While a run starts Chat shows the Thinking box (`Thinking…`) and the send button reads `Sending…`; `Probing {model} · nth try` stays off the frontend and only `Could not reach {model} after 3 tries` surfaces.
