# 0.14.21 changelog (Windows patch)

**Purpose:** reference for what must be inside the 0.14.21 `setup.exe`. Same rule as 0.14.1: nothing here counts as shipped until it is staged (`host.cjs` + renderer), packed (`pnpm desktop:build`), installed, and driven on the packaged app (`doctor --desktop`). Version follows Kyo's 2026-09-07 rule: after 0.14.2 the next releases are `0.14.21`, `0.14.22`, … (never `0.14.3+`, never `0.15`).

Append-only. Working-tree changes on `main` after the 0.14.2 release (`6aad7cd`). Platform rules: [`apps/desktop/platform/README.md`](../../apps/desktop/platform/README.md).

## Onboarding: paste into the API key field — 2026-09-07

- **Bug:** fresh install, onboarding screen, Ctrl+V and right-click Paste did nothing in the API key field, so first-run users could not get a key in. The React form was fine; the Electron shell called `Menu.setApplicationMenu(null)`, which removes the Edit roles that back Ctrl/Cmd+V, and Electron never shows a right-click menu on its own.
- **Shell:** `apps/desktop/edit-menu.cjs` (new): `applicationMenuTemplate(platform, productName)` (Edit menu on all OSes, App + Window menus on macOS), `contextMenuTemplate(params)` (Cut/Copy/Paste/Select All on editable fields, Copy on selected text), `installApplicationMenu`, `attachContextMenu`. `main.cjs` installs the menu instead of `null` and attaches the context menu to the window; `autoHideMenuBar` keeps the bar hidden on Windows (Alt reveals it). `package.json` ships `edit-menu.cjs` in `build.files` and runs `edit-menu.test.cjs` in `test`.
- **Tests:** `apps/desktop/edit-menu.test.cjs` (node:assert; guards that the application menu is never null again). Smoke-built under real Electron 35.7.5.
- **Verify on the installed app:** onboarding key field accepts Ctrl+V and right-click → Paste; Chat composer Ctrl+A/C/V round-trip.

## Settings: editable gateway endpoint — 2026-09-07

- **What:** the owner can point the OpenAI-compatible endpoint somewhere other than Toko Token from Settings (own gateway, or a local model server on 127.0.0.1). Onboarding still shows the branded endpoint read-only; copy now says it can be changed later in Settings.
- **Host:** `packages/host/src/settings-store.ts` replaces `lockGateway` with `withGatewayDefault`: empty → branded default (`resolvedGatewayBaseUrl()`), otherwise the saved value (trimmed, no trailing slash). `saveSettings` no longer overwrites `openaiBaseUrl`; `assertSavedEndpoints` still rejects anything that is not HTTPS or loopback HTTP. `handlers/settings.ts` accepts `openaiBaseUrl` in `POST /api/v1/settings`.
- **Web:** `settings-page.tsx` adds **Endpoint URL** (`settings-endpoint`) above the key, a one-line HTTPS hint, and **Use Toko Token (api.tokotokenai.com)** (`settings-endpoint-reset`) whenever the value differs from the branded default. Save posts `openaiBaseUrl` with the key.
- **Tests:** `packages/host/src/settings-endpoint.test.ts` (7: default, custom HTTPS persists across reload and across saves that omit the field, empty resets, loopback HTTP allowed, remote HTTP rejected and previous value kept, non-URL rejected, branded flavor default). Replaces `settings-lock.test.ts`.
- **Verify on the installed app:** set a bogus HTTPS endpoint → Save → Chat fails with a clear error; reset link restores Toko Token; relaunch keeps the saved endpoint.

## Updates control moved to the rail — 2026-09-07

- **What:** the Updates strip left Settings. The rail footer now reads theme toggle · **updates icon** · collapse. The icon shows an accent dot when a version is downloadable/installed-ready and pulses while checking/downloading. Clicking opens a small panel (fixed-positioned, so the `overflow-hidden` rail cannot clip it) with the same status line and **Check for updates** / **Update and restart** actions plus Close. Escape or an outside click closes it. Collapsed rail stacks the two icons vertically. Branded flavors render no icon.
- **Web:** `apps/web/lib/use-app-updates.ts` (new hook with the updater state machine formerly inside the panel), `components/app-updates.tsx` now exports `AppUpdatesButton`, `app-rail.tsx` mounts it, `settings-page.tsx` no longer imports it. `lib/app-updates-copy.ts` gains `updateBadge`, `isInstallAction`, `updateButtonTitle`.
- **Testids:** `app-updates` (wrapper), `app-updates-toggle`, `app-updates-badge`, `app-updates-panel`, `app-updates-status`, `app-updates-check`, `app-updates-install`, `app-updates-close`, `rail-footer`. The old Settings block is gone; update `features/settings.md` / `features/desktop.md` drives accordingly.
- **Tests:** `lib/app-updates-copy.test.ts` (+8 for the new helpers). Web Vitest 106 green.
- **Verify on the installed app:** icon visible in both rail widths; click → panel; Check for updates reports a state; from an installed 0.14.2, 0.14.21 shows the dot and Update and restart relaunches.
