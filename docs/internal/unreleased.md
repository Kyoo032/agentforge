## Findings from the harness pass — 2026-09-15

Product bugs the pstack mapper turned up while writing [`maps/`](maps/README.md). **Found by the mapper, not fixed** — the mapping run is read-only, so every one of these is still live on `cursor/id-locale-harness-chat-layout` at `b9f931a`. Tracked as P7–P15 in [`blockers-2026-09-15.md`](blockers-2026-09-15.md) section 1.

- **Chat swallows `403 gateway_blocked`.** The host emits the blocked body flat, with `error` as a *string* (`packages/host/src/errors.ts:20-25`), precisely so `parseGatewayBlocked` (`apps/web/lib/gateway-gate.ts:134`) can read it — but that parser is wired only into `settings-page.tsx` and `onboarding-screen.tsx`. The composer does `payload.error?.message ?? t("chat.error.runFailed")` (`apps/web/components/chat-composer.tsx:244-246`), and `.message` on a string primitive is `undefined`, so a closed gate shows the generic "run failed" copy in Chat instead of the invalid-key / unreachable reason. Documented in [`maps/chat-send.md`](maps/chat-send.md).
- **The renderer's stream watchdog never leaves first-token mode.** `readSse` calls `dog.touch()` only (`apps/web/components/chat-composer.tsx:254`, `:314`); `touchOutput()` is never called on this path, and `streaming` flips only inside `touchOutput` (`packages/core/src/runtime/stream-watchdog.ts:168`). By the one deadline rule (`packages/core/src/runtime/stream-watchdog.ts:88-97`) the client-side deadline therefore stays `startedAt + ttfbMs` for the whole run, and repeated touches re-arm a timer that fires at the same instant — so a long, actively-streaming answer can be aborted client-side while tokens are visibly arriving. The host-side guards do call `touchOutput` (`packages/host/src/run-stall.ts`, via `isRunOutputEvent`), so the asymmetry is renderer-only. Documented in [`maps/chat-send.md`](maps/chat-send.md).
- **Probing has no UI, and its copy is unreachable.** `ChatComposer` declares `onProbing?: (info: { attempt, attempts, message })` (`apps/web/components/chat-composer.tsx:33`) and parses `run.probing`, then discards the payload and calls `onStarted?.()` (`:131-133`); a repo-wide grep finds no other reference to `onProbing` at all, so `ChatSession` never passes it. The string `chat.error.couldNotReach` exists in both catalogs (`apps/web/locales/en/chat.json:114`, `apps/web/locales/id/chat.json:114`) with zero references in `apps/web`. This is why `features/chat.md`'s rule that probe copy must not appear on the frontend holds trivially — it cannot. Documented in [`maps/chat-send.md`](maps/chat-send.md).
- **An `injectionGuardBypass` leaves no audit line.** When the per-workspace bypass is true the scan is skipped outright — `bypass ? null : scanInjection(...)` (`packages/host/src/knowledge.ts:409-415`, `packages/host/src/knowledge-ingest.ts:79-85`) — with no log entry; only actual blocks get a `console.warn`. Nothing on disk or in the UI records that a given source was ingested unscanned, and no test exercises the bypass on the knowledge path (the flag is only covered in `packages/core/src/secrets.test.ts` and non-knowledge job paths). Documented in [`maps/knowledge-ingest-loop.md`](maps/knowledge-ingest-loop.md).
- **An uploaded `.html` file is indexed with its raw markup.** `sourceKind()` routes any `text/*` mime — `text/html` included — to the raw UTF-8 branch (`packages/host/src/knowledge-extract.ts:44-60`, `:181-182`), unlike URL ingest, which always runs `htmlToText` (`packages/host/src/knowledge.ts:481-483`). Tags, scripts and attributes therefore become chunk text and retrieval surface. Documented in [`maps/knowledge-ingest-loop.md`](maps/knowledge-ingest-loop.md).

## anydoc packing (unreleased — one install step outstanding)

`packages/host/src/file-extract` converts .pdf / .docx / .pptx / .xlsx / .odt / .rtf / .epub locally
through `@firecrawl/anydoc`, a napi-rs module whose per-platform binary is a real `.node` file. The
host is bundled into `apps/desktop/host.cjs` by esbuild, so the binary cannot be inlined: it has to
travel as a real `node_modules` entry and be readable outside the asar.

**Done in tree (no install needed):** `apps/desktop/package.json` `asarUnpack` now also lists
`**/node_modules/@firecrawl/anydoc/**` and `**/node_modules/@firecrawl/anydoc-*/**` (the platform
packages `@firecrawl/anydoc-win32-x64-msvc`, `-darwin-arm64`, `-darwin-x64` are siblings, not nested).
No esbuild change is needed: `file-extract/anydoc.ts` loads the module through `createRequire`, which
esbuild leaves as a runtime require rather than trying to bundle a `.node` file.

**Outstanding — needs `pnpm install`, so it was deliberately not run here:**

1. Add the dependency to `apps/desktop/package.json` so electron-builder collects it (it only walks
   the desktop package's own production dependencies; the root hoist is not enough):
   ```json
   "dependencies": {
     "@firecrawl/anydoc": "^0.2.4",
     "better-sqlite3": "^13.0.3",
     ...
   }
   ```
2. `corepack pnpm install` at the repo root, to materialise
   `apps/desktop/node_modules/@firecrawl/anydoc` and update `pnpm-lock.yaml`.
3. **No rebuild step.** Unlike better-sqlite3 and keytar, anydoc ships prebuilt napi binaries and is
   ABI-independent, so `rebuild-natives` does not need a new `-w` flag and electron-builder's default
   `npmRebuild` has nothing to do for it.
4. **macOS (Docker path, `apps/desktop/platform/macos/docker/build-mac.sh`)** — that script runs with
   `-c.npmRebuild=false` and hand-places the darwin binaries for better-sqlite3 and keytar. anydoc
   needs the same treatment only if the Linux install did not fetch the darwin optional packages:
   before the `electron-builder --mac` line, make sure
   `apps/desktop/node_modules/@firecrawl/anydoc-darwin-arm64` and `-darwin-x64` exist (install with
   `--config.supportedArchitectures` or copy them in, exactly as the keytar tarball is unpacked).
   **Not run — this needs a mac machine / the release pipeline.**

**If any of the above is skipped the app still works.** `extractFile` catches the missing binding,
logs `file-extract: native converter unavailable, falling back`, and degrades to the extractors that
predate it (pdfjs, JSZip+xmldom, SheetJS). Only .pptx / .odt / .rtf / .epub become unreadable, which
is what they were before. `packages/host/src/file-extract/fallback.test.ts` covers that path.
