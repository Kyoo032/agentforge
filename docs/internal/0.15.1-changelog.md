## Updater

`electron-updater` aborts the in-flight Electron request when GitHub redirects, then starts another. That abort rejects the same promise the new request would resolve (`node_modules/electron-updater` `electronHttpExecutor.js` `addRedirectHandlers`, and `builder-util-runtime` `httpExecutor.js` `addErrorAndTimeoutHandlers`). The public repo rename answers `https://github.com/Kyoo032/DPSBuddy/releases.atom` with `301` to `Kyoo032/Nultron` (measured 2026-09-28). `latest.yml` then `302`s to `release-assets.githubusercontent.com`. When the abort wins, the panel shows a connection error. The installed log at `%APPDATA%\DPSBuddy\logs\updater.log` has five successful checks and no error line, which matches a race rather than a dead feed. `curl` of the published `latest.yml` through the old name returned `200` in 0.82s with two redirects.

The new build retries `ECONNRESET`, `ETIMEDOUT`, `net::ERR_*`, and "Request has been aborted by the server", and it does not retry a 404 or a checksum failure. A retry in progress stays on "checking". The feed owner/repo baked into the new installer is `Kyoo032/Nultron`.
